## R5.1 规则

- 本阶段优先复用现有表，不因体验调整立即重构数据库。
- 新增候选承载层必须包含 `project_id`、来源章节、来源修订、Proposal、候选状态、证据和创建时间。
- 正文提取的每条证据必须能定位到 `ManuscriptRevision`、block 和字符范围。
- 正式知识仍通过既有审核和原子定稿事务写入。

## 本阶段迁移与后续候选

具体版本号在切片开始编码前分配并同步到本清单。当前状态：

| 能力 | 最低持久化要求 | 状态 |

| 规划项显式状态 | 规划项语义状态和作者承诺，不覆盖原内容 | 已落地（37） |
| 正文提取候选 | 类型、负载、证据、状态、来源修订和 Proposal | 已落地（38）；五类候选均接入正式采用或待审知识候选 |

| 统一候选元数据 | 根据真实使用评估 `story_state`、`visibility`、`hardness` 等 | 暂缓，待使用反馈 |

## 回滚与兼容

- 每项迁移必须支持空库、已有项目和失败事务回滚。
- 展示层 JSON 不得成为候选或正式状态的唯一真值来源。
- 旧数据缺少显式状态时按 `UNSET` 或无状态解释，不自动升级为 `CONFIRMED`。
- 版本 40 在关闭外键检查的短事务中重建讨论会话表，保留既有会话、消息和候选，并扩展场景、选区范围。
