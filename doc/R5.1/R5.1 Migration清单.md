2026-10-09 的 P0/P1 首批没有新增迁移；第二批增加迁移 49。阶段进度以 `doc/优化/分阶段实施.md` 为准。
P1 第三批候选编辑保护与隐藏查询收敛只调整前端，未增加表、字段、迁移或 IPC 命令。
未提交提取负载仍是界面内存，不被迁移 49 的正常正文草稿表承载；提取负载的后端版本 CAS 未在本批实现。

P2 首批来源定位没有新增表、字段或迁移，schema 仍为 49，仅增加只读 `get_manuscript_source` IPC。
来源查询不修改历史正文、草稿、锚点或正式知识；失效证据不自动修补。
正文搜索来源版本在新索引及旧索引读取时规范化为 `manuscript:<revision UUID>`；真实 block ID 使用字符串而非强制 UUID。
搜索索引仍是可重建派生数据，不将查询片段或浏览器返回位置持久化为正式来源。

2026-10-10 P2 第二批讨论与规划往返未新增迁移，schema 仍为 49。
新增只读 `get_discussion_source`、`list_planning_discussion_sources` IPC，从已有晋升候选、会话、原消息和目标规划派生历史流转记录，不复制或回填 `references_json`。
讨论晋升沿用现有事务，但更新已有规划时补齐 `version = planning_sections.version + 1`；新规划仍使用迁移 49 的默认版本 1。
正式内容、作者理由、引用与已有正式状态保持独立；历史来源缺失、项目/消息不一致或目标归档时不自动修复或删除记录。

迁移 49 在独立事务中创建 `manuscript_drafts`，为 `planning_sections` 增加初始值为 1 的 `version`。
空规划项的预期版本为 0；手工和内部更新均递增版本。草稿清空后保留版本记录，防止旧窗口重新写入旧内容。
不复制、删除或重分类既有正文修订、RecoveryLog、规划内容或知识审核数据。
失败时回滚本迁移的建表及版本记录，修复失败原因后可重试；升级后不承诺旧版程序降级兼容。

2026-10-10 P2 第三批增加迁移 50 `chapter_entity_references`：

- 独立事务创建 `chapter_entity_reference_sets`、`chapter_entity_references`、实体逆查索引及迁移记录，失败全部回滚，可重试。
- 每章一个关联集合版本及至多八个唯一稳定实体 ID；集合尚不存在时预期版本为 0，清空保留递增版本记录。
- 替换关联和版本递增同事务，项目、有效章节、当前实体修订与新增归档资料均在写入时检查。归档章可读不可写，既有归档关联可保留或移除。
- 旧项目不自动生成关联，不复制实体修订，不修改正文、规划 `references_json`、证据或正式事实。
- 新增 `list_entity_cards`、`get_chapter_entity_references`、`save_chapter_entity_references`、`list_entity_chapters` 四个 IPC，总计 138 个客户端命令。
- 上下文复用当前精确修订，来源版本统一为 `entity:<entity UUID>:revision:<revision UUID>`，导入文件名仍保留为实体来源说明，不用它替代精确修订。

## 2026-10-10 P2 第四批：资料只读查询

- 数据库仍为 schema 50，没有新增迁移、表、字段或依赖，也不回填历史资料来源。
- 新增 `get_summary_material`、`get_writing_card` 两个只读 IPC，核对当前项目、预期项目和精确对象 ID；客户端命令共 140 个。
- 查询已失效摘要、候选摘要或停用卡片不修改其状态；读取测试核对 SQLite 总变更数不增加，且重开项目保留原内容与状态。
- 规划导航复用既有节点和规划查询，自动章节摘要的正文来源复用 `get_manuscript_source`；不改写正文、规划、证据或章节关联。类型契约生成仍延期至 P3。

## 2026-10-10 P3 首批：提取候选版本

2026-10-10 P3 首批增加迁移 51 `extraction_item_versions`：

- 独立事务为 `chapter_extraction_items` 添加 `version INTEGER NOT NULL DEFAULT 1 CHECK(version > 0)`，与迁移登记一起提交；失败回滚字段和登记，可重试。
- 保留四种历史审核状态、JSON 负载、证据、正式对象 ID 与时间，不回填领域对象，不重写正文或知识历史。版本只从升级后开始计数。
- 保存、延期、拒绝、采用必填项目/章节/状态/版本目标，每次成功递增版本；更新和回执读取同事务，采用继续同事务创建领域对象并更新提案汇总。
- 三个 mutation IPC 改用必填 `ExtractionItemTarget`，没有 unchecked 回退。删除四个无调用旧 IPC 入口后，客户端命令为 137 个；完整 Rust/TS 类型生成仍待后续 P3。
- P1 的提取负载后端 CAS 延期项在此落实；未提交候选编辑仍不是自动持久化草稿，升级不承诺旧版降级兼容。

## 2026-10-10 P3 第二批：批量事务，无新迁移

- schema 保持 51，不新增表、字段、迁移或依赖，不改写或删除历史资料。
- 新增 `import_entities`、`adopt_plan_batch`，客户端命令共 139 个；请求必填项目，规划采纳另必填父节点修订、精确源规划及原源版本。
- 复用实体事务写入、规划版本保存及节点创建逻辑。实体首修订与索引整批提交；规划子节点、章节、历史修订、非空内容执行卡、源候选消费、派生失效及索引整批提交。
- 原版本 0 的未保存源可提交一次；采纳后保留递增规划版本以拒绝旧请求。拆章正式字段从数据库保留，不接受请求将其一起改写。
- 同事务内读取回执，失败不留下部分数据；实体导入未新增持久化幂等收据，回执丢失须重读核对，不承诺跨请求 exactly-once。

## R5.1 规则

- 本阶段优先复用现有表，不因体验调整立即重构数据库。
- 新增候选承载层必须包含 `project_id`、来源章节、来源修订、Proposal、候选状态、证据和创建时间。
- 正文提取的每条证据必须能定位到 `ManuscriptRevision`、block 和字符范围。
- 正式知识仍通过既有审核和原子定稿事务写入。

## 回滚与兼容

- 每项迁移必须支持空库、已有项目和失败事务回滚。
- 展示层 JSON 不得成为候选或正式状态的唯一真值来源。
- 旧数据缺少显式状态时按 `UNSET` 或无状态解释，不自动升级为 `CONFIRMED`。
- 版本 40 在关闭外键检查的短事务中重建讨论会话表，保留既有会话、消息和候选，并扩展场景、选区范围。
