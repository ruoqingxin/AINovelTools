# R5.1 已知风险

| 风险 | 影响 | 缓解与验收 |
|---|---|---|
| 解除规划阻断后 AI 上下文过少 | 正文可能偏离作者意图 | 提示缺失依据并把未知视为有效状态；保留当前指令、选区、锁定内容和正文修订边界 |
| AI 建议被误当正式内容 | 污染计划或知识 | 所有 AI 输出先进入 Proposal 或候选；正式写入必须由作者确认 |
| 正文提取制造大量待办 | 创作者被审批淹没 | 手动触发、重复内容优先累计证据、低优先级内容折叠 |
| 证据无法定位到原修订 | 候选不可追溯 | 强制保存章节、修订、block、范围和原文哈希 |
| 候选类型被伪装成 Fact | 领域语义失真 | 不使用 Fact 承载角色或伏笔；需要时增加轻量提取候选表 |
| 讨论内容直接改正史 | 可靠性倒退 | 会话表与正式领域表隔离，只能转为候选或临时笔记 |
| 上下文声称读取完整设定 | 模型幻觉被强化 | 无命中时返回明确空语义和来源限制 |
| 文档版本再次漂移 | 迁移和验收依据不一致 | 以运行时 schema version 和 R5.1 Migration 清单共同核对 |

## 2026-10-09 创作闭环优化补充

- 普通正文草稿仍通过现有 RecoveryLog 提供延迟保护，尚未拥有与异常恢复独立的持久化生命周期；不能视为零延迟自动保存。
- 规划保存仍缺少正文同等级别的并发版本检查，异步回写保护也需后续切片补齐。
- 助手切换已保留 AI 面板状态，任务流按当前任务隔离；隐藏面板的查询和轮询预算仍需收敛。
- 原文证据可以就地查看，打开已保存正文不会重载章节；精确到原修订及 block 的定位仍属于 P2。
- 浏览器模拟 IPC 验证已经通过，但不替代真实桌面、多窗口和真实模型验收。
- 阶段进度与证据见 `../优化/分阶段实施.md`。
