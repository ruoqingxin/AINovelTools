## 目标

R5.1 不重构 R0-R5 的可靠性骨架，而是把现有能力调整为渐进式共创闭环：

```text
一句话灵感
  -> 可选规划
  -> 正文草稿
  -> Proposal / 候选
  -> 作者确认
  -> 正式正文和知识
  -> 相关上下文继续写作
```

## 实施顺序

### 阶段 1：解除错误的写作阻断（已完成）

- 规划和人物卡缺口改为建议，不再阻止保存正文或生成 Proposal。
- 新建作品提供“一起规划”和“先写一段看看”两条入口。
- 快速入口只要求一句话核心，可选填写规模和第一卷方向。
- 保留当前指令、已锁定内容、Proposal 边界和作者显式选择的严格审核策略。

### 阶段 2：未知状态与统一候选语义（已完成）

- 规划项支持 `UNSET`、`UNKNOWN`、`DEFERRED`、`AUTHOR_RESERVED`、`AI_SUGGESTED`、`CONFIRMED`、`LOCKED`、`RETIRED`。
- AI 建议不能作为正式规划、事实或实体。
- 候选至少支持待审、接受、部分接受、延期和拒绝。

### 阶段 3：正文到候选的纵向切片（首版完成）

- 指定 `ManuscriptRevision` 后手动发起“提取本章候选”。
- 首批覆盖角色、地点、势力、物品、概念、事实、关系、事件、能力和伏笔候选。
- 每条候选绑定章节、修订、block、文本范围、原文哈希和 AI Proposal。
- 复用现有审核、证据和定稿边界；新增角色可编辑确认后创建 `Entity` / `EntityRevision`。

### 阶段 4：相关上下文切片（已完成）

- 使用现有 SQLite 查询和 FTS5，不引入向量检索。
- 仅传递当前章节相关的正式知识、计划、状态、伏笔和知识边界。
- 无命中时明确显示“未检索到相关正式知识”，不得声称已读取完整设定。

### 阶段 5：轻量作品级剧情讨论（首版完成）

- 保存作品级会话和消息。
- 支持全书、当前卷、当前章节、场景和选区范围；选区文本随会话持久化并写入讨论上下文。
- 讨论结果先进入临时笔记或候选内容，不直接写正式对象。

### 阶段 6：统一元数据（暂缓）

- 仅在真实使用确认重复状态和查询需求后，评估 `story_state`、`author_commitment`、`visibility`、`hardness` 等字段。
- 首版不建设统一 `story_claims` 真值表。

## 每阶段门禁

1. 更新领域契约和错误路径。
2. 更新 typed IPC 与前端客户端。
3. 覆盖加载、空、成功、冲突、失败和恢复状态。
4. 完成 Rust、SQLite、TypeScript 和关键交互测试。
5. 同步 FeatureCatalog、Migration 清单、已知风险与验收记录。

## 最小闭环

首版必须优先完成：

```text
只填写一句话核心
  -> 创建章节
  -> 保存正文
  -> 提取候选角色
  -> 作者确认
  -> 后续上下文回用
```

## 非目标

- 向量数据库、Tantivy、ReviewCase 和独立 Worker。
- 完整 Workflow Runtime、多角色工作流和统一 `story_claims` 表。
- 以完整世界观、人物卡、章节执行卡或规划完成百分比阻断普通写作。
