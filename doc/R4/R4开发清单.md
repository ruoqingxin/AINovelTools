## 1. 目标与边界

R4 建立可长期使用的故事设定库、基础检索和本机可靠性能力：

```text
实体与版本
    -> Story Bible 管理
    -> SQLite FTS5 投影与搜索
    -> 摘要/风格/技巧材料
    -> ContextAssembler 结构化查询和关键词查询
    -> 持久化后台任务
    -> 备份、恢复、健康扫描和启动诊断
```

R4 的检索结果和 AI 新生成细节只能作为有来源的上下文或候选材料，不能自动成为正式事实。正式事实、证据锚点、知识审核和章节定稿属于 R5。

## 2. 阶段门禁

进入 R4 编码前必须完成：

- [ ] 完成 R3 真实云端 API 冒烟：Chat、Embedding、续写、重写、润色、摘要、取消和鉴权失败。
- [ ] 确认 AI 失败或取消不改变正文和修订历史。
- [ ] 对 R0-R2、R3 和长期清单的每一项标记：`本阶段实现`、`继续延期` 或 `取消`。
- [ ] 将复核结果同步到 R4 开发流程、FeatureCatalog、Migration 清单、已知风险和阶段验收记录。
- [ ] 确认 API Key 不进入项目数据库、日志、诊断包或前端回读状态。

## 3. 不可违反的规则

1. 正式历史只追加，不通过实体、正文或索引更新动作覆盖历史版本。
2. SQLite 是正式数据源；FTS5 是可删除、可重建的投影。
3. 实体、摘要、风格卡和技巧卡必须带来源、版本和生命周期状态。
4. 无来源或未批准的 AI 内容必须显式标记为候选，不得伪装成正式知识。
5. 后台任务必须可取消、可重试、可恢复，并记录失败原因。
6. 备份必须经过恢复到新目录和哈希校验，不能只验证压缩包生成成功。
7. 诊断包默认不得包含正文、数据库、Prompt、完整模型响应、API Key、附件和完整用户路径。
8. UI 必须覆盖加载、空、成功、运行、取消、失败、冲突和恢复状态，并完成桌面与窄屏检查。

## 4. UI 参考使用规则

`doc/UI参考/` 下的截图和工具界面可作为开发过程中的交互、布局、信息层级和视觉细节参考。参考资料包括 WinkNoval、妙笔生花等工具的主界面、创作界面和设置界面。

使用参考界面时必须遵守以下规则：

1. 参考界面只提供启发和对比，不是本项目的产品规范、功能清单或实现模板。
2. 最终实现必须优先符合本项目已有的领域模型、数据语义、页面结构、交互路径、权限边界和技术框架。
3. 不直接复制其他工具的品牌、文案、图标、视觉资产、页面结构或交互细节；需要结合本项目用户流程重新设计。
4. 参考某个界面时，应先说明借鉴目标，例如信息层级、布局方式、状态表达、编辑效率或设置组织方式。
5. 参考界面与本项目框架发生冲突时，以本项目框架、阶段范围和数据契约为准。
6. 不得为了贴近参考图而引入 R4 未批准的功能、空 UI、无真实调用者的抽象或 R5/R6 能力。
7. UI 方案落地前仍需完成桌面与窄屏检查，并覆盖加载、空、成功、运行、取消、失败、冲突和恢复状态。

参考目录的定位是“设计参考库”，不是运行时资源目录；除非明确批准，不将其中截图或素材打包进应用。

## 16. R4 完成判定

满足以下条件后，R4 才能标记完成：

1. 五类 Story Bible 实体可创建、编辑、版本化、归档、恢复和检索。
2. 章节、正文修订、规划和实体均可通过 SQLite FTS5 搜索并定位来源。
3. 多精度摘要、风格规则卡和写作技巧卡可持久化并接入上下文组装。
4. 备份可恢复到新目录，关键项目和正文哈希一致。
5. 启动恢复、健康扫描、CrashMarker、RecoveryLog 和诊断包可用。
6. R4 第一批后台任务可取消、可重试、可恢复。
7. 所有失败路径不伪造成功，不污染正文、正式实体版本或修订历史。
8. R5/R6 能力没有以空 UI、空结果或无调用者抽象提前进入系统。

## 17. 明确继续延期

以下内容不进入 R4：

- `Relation`、`Fact`、`Event`、`Belief`、`Foreshadowing`、`EvidenceAnchor`。
- `WorldState`、`KnowledgeVersion`、`ChapterChangeSet`、知识审核和章节定稿。
- AI 双输出 Schema、事实使用报告、冲突检测和候选知识批准流程。
- 向量索引、混合检索、Tantivy 和高级检索规划。
- 长章节按场景生成、状态接续、合章和多角色工作流。
- 完整 Task Runtime、Lease、Checkpoint、ResourceGovernor、独立 Worker 和 Workflow Runtime。
- 多窗口编辑会话治理、导入导出和项目交换包。

这些能力只有满足 `doc/后续流程/长期按需能力与延期项.md` 的触发门槛，并完成单独 ADR、基准、失败路径、隐私检查和验收报告后，才能进入后续阶段。

## 18. 下一流程入口

R4 完成后，必须新增或更新 R4 延期清单，并将其加入 `doc/后续流程/README.md` 的阶段阅读矩阵。进入 R5 前，必须重新复核全部延期项，明确每项是 R5 实现、继续延期还是取消。
