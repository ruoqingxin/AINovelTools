## 执行范围

- 日常前端改动：`pnpm test:ui:changed`。按相对 HEAD 的已暂存、未暂存和新文件选择关联测试；公共配置变化可能触发全量。干净工作区没有测试可选，不是全量通过。
- 明确的前端模块：`pnpm test:ui src/views/coauthor-view.test.tsx`。文件参数可替换，不额外插入 `--`。
- 已提交的改动：显式指定相关文件，或使用 `pnpm --filter @ainoveltools/desktop exec vitest run --changed <base>`。
- Rust 局部改动：`cargo test -p <crate> <module-filter>`。迁移、共享存储、项目切换、取消和正式采用等扩大到相关模块或整个 crate。
- 原生命令、参数和序列化变化：追加 `pnpm check:ipc`。普通样式或文本调整不需要反复重跑原生契约生成。
- 工具或其数据变动才跑相应工具测试；安装、恢复、中断和模型评测按涉及的功能选择，不作为每次界面调整的固定动作。
- 用户流程变化需选取相应浏览器或原生流程验收；小改动不重复全部历史验收矩阵。
- 发布、跨模块改造或无法判断影响范围：保留 `pnpm test` 全量门禁，以及相关原生验收。自动测试通过不代表模型语义质量达标。

后续协作规则同步到根目录 `AGENTS.md`，优先复用和扩展既有用例，不按版本机械增加整套测试。
