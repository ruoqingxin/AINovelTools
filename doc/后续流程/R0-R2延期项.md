# R0-R2 延期项

## 前端展示 UI 固化标准
- 前端展示 UI 在不影响性能的前提下，必须美观、清晰、易用。
- 首次实现功能时确定布局、信息层级、视觉规范、控件规范、完整状态和响应式行为，形成稳定基线。
- 后续功能优先复用既有 UI；除非有明确的可用性、性能或业务依据，不进行大规模改版。
- UI 调整须保持操作路径和数据语义连续，并完成桌面与窄屏检查。

以下内容经过 2026-08-27 复核后，不作为当前 R0-R2 核心闭环的阻塞项。它们保留正式实施位置，并在出现对应需求或进入后续阶段时实施。

开始下一阶段前必须先阅读 `doc/后续流程/README.md`，再按其中的阶段阅读矩阵复核本文件。

## R3 复核结果

- `继续延期至 R4`：使用专用工具从 Rust DTO 自动生成 TypeScript 文件。当前契约一致性检查仍能覆盖现有 IPC；DTO 数量或漂移风险达到门槛时再切换。
- `部分完成，剩余继续延期`：章节工作区四页签已完成；规划树独立路由只有出现真实导航需求时再实施。
- `部分完成，剩余继续延期至 R4`：模型配置已实现；统一 ProjectSettings、写作风格和项目隐私设置等待对应正式字段。
- `继续延期至 R4`：最近项目列表作为应用级数据保存，不进入小说项目数据库。

## R4 日常可靠性阶段

- 完整 CrashMarker、迁移中断检测和诊断包。
- 真实 Tauri 自动化启动、文件选择器和窗口失败诊断。
- RecoveryLog 自动压缩、保留策略和后台清理任务。
- 完整备份包、哈希校验及恢复到新目录演练。
- 大型规划树虚拟化和查询分页。

## 编辑器后续增强

- 更成熟的段落 diff 算法和段内字符差异。
- 三方合并冲突块的逐项“采用当前/采用草稿/手工编辑”工具。
- Tiptap 文档 Schema 的多版本迁移框架。
- 完整快捷键、键盘导航和无障碍测试。
- 多窗口启用后的编辑会话冲突处理。

## 明确不提前进入 R0-R2

- AI Provider、Prompt、ContextAssembler 和 AiProposal：属于 R3。
- Story Bible、实体修订和 FTS5：属于 R4。
- ChangeSet、知识审核和章节定稿：属于 R5。
- Tantivy、向量检索、Workflow Runtime、独立 Worker 和复杂可视化：满足引入门槛后进入 R6 或更后阶段。

## 延期原则

延期能力不得用虚假成功或空结果冒充已实现。FeatureCatalog 应保持 `DECLARED`、`PARTIAL` 或 `DISABLED`，直到对应测试和验收完成。
