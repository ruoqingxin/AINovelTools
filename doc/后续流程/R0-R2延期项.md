# R0-R2 延期项

以下内容经过 2026-08-27 复核后，不作为当前 R0-R2 核心闭环的阻塞项。它们保留正式实施位置，并在出现对应需求或进入后续阶段时实施。

## R3 前或 R3 同期

- 使用专用工具从 Rust DTO 自动生成 TypeScript 文件。当前已有契约一致性检查；当 R3 引入大量 AI DTO 时再切换为完整代码生成。
- 将规划树拆成独立路由和多标签工作区。
- ProjectSettings 扩展。模型、写作风格和隐私设置在 R3 有真实字段后统一设计。
- 最近项目列表。作为应用级数据保存，不进入小说项目数据库。

## R4 日常可靠性阶段

- 完整 CrashMarker、迁移中断检测和诊断包。
- 真实 Tauri 自动化启动、文件选择器和窗口失败诊断。
- RecoveryLog 自动压缩、保留策略和后台清理任务。
- 完整备份包、哈希校验及恢复到新目录演练。
- 大型规划树虚拟化和查询分页。

## 编辑器后续增强

- 更成熟的段落 diff 算法和段内字符差异。
- 三方合并冲突块的逐项“采用当前/采用草稿/手工编辑”工具。
- Tiptap 文档 Schema 的多版本迁移框架。
- 完整快捷键、键盘导航和无障碍测试。
- 多窗口启用后的编辑会话冲突处理。

## 明确不提前进入 R0-R2

- AI Provider、Prompt、ContextAssembler 和 AiProposal：属于 R3。
- Story Bible、实体修订和 FTS5：属于 R4。
- ChangeSet、知识审核和章节定稿：属于 R5。
- Tantivy、向量检索、Workflow Runtime、独立 Worker 和复杂可视化：满足引入门槛后进入 R6 或更后阶段。

## 延期原则

延期能力不得用虚假成功或空结果冒充已实现。FeatureCatalog 应保持 `DECLARED`、`PARTIAL` 或 `DISABLED`，直到对应测试和验收完成。
