# 长期按需能力与延期项

## 前端展示 UI 固化标准
- 前端展示 UI 在不影响性能的前提下，必须美观、清晰、易用。
- 首次实现功能时确定布局、信息层级、视觉规范、控件规范、完整状态和响应式行为，形成稳定基线。
- 后续功能优先复用既有 UI；除非有明确的可用性、性能或业务依据，不进行大规模改版。
- UI 调整须保持操作路径和数据语义连续，并完成桌面与窄屏检查。

## R6 按需能力

- Tantivy 全文索引。
- Embedding 向量索引和混合检索。
- 高级 `ContextAssembler` 和上下文规划 AI。
- 按场景生成、状态接续、合章和多角色审核工作流。
- 完整 Task Runtime、Lease、Checkpoint、ResourceGovernor、补偿和复杂优先级。
- 独立 Worker。
- 版本化 Workflow Runtime 和工作流画布。
- 时间线、关系图、伏笔和节奏分析。
- LARGE/STRESS 数据集性能工程和全书一致性扫描。
- 跨章节批量审核需要的 `ReviewCase`、`ReviewItem`。

## R7 可选扩展

- Markdown、DOCX、EPUB、PDF 等导入导出。
- 声明式 Prompt、实体和工作流模板。
- 多窗口及跨窗口编辑会话治理。
- 项目交换包。

## 长期不在当前产品范围

- 账号与公网身份系统。
- 云端托管和多人实时协作。
- 商业订阅与计费。
- 任意代码插件。
- 公网遥测。

这些事项只有产品范围正式变化并更新 ADR、隐私边界和总路线后才能进入开发。

## 引入门槛

| 能力 | 引入门槛 |
| --- | --- |
| 独立 Blob Store | SQLite 项目达到已定义规模并出现可复现的备份、读取或空间问题 |
| Tantivy | FTS5 未达到基准，或需要其分词、评分和异步索引能力 |
| 向量检索 | 已有稳定 EvidenceAnchor、来源版本和可评估的召回数据集 |
| 通用 Command/Query Bus | 出现动态模块、跨进程协议或大量统一中间件需求 |
| 完整 Registry 系统 | 出现动态发现或第三方声明式扩展需求 |
| 完整 Task Runtime | 至少有多个需要恢复、Checkpoint、租约或资源治理的长任务 |
| 独立 Worker | 任务会显著阻塞桌面进程、占用大量内存或需要故障隔离 |
| Workflow Runtime | 已有稳定 Command、持久化 Job 和至少三个真实重复工作流 |
| ReviewCase | ChangeSet 内审核无法满足批量队列或多来源治理需求 |
| 多窗口 | 已解决项目锁、同章节并发和跨窗口事件同步设计 |

每项能力必须单独完成 ADR、基准、失败路径、隐私检查和验收报告，不能因为进入 R6 就一次全部启用。
