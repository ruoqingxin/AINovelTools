# 后续流程强制入口

## 前端展示 UI 固化标准
- 前端展示 UI 在不影响性能的前提下，必须美观、清晰、易用。
- 首次实现功能时确定布局、信息层级、视觉规范、控件规范、完整状态和响应式行为，形成稳定基线。
- 后续功能优先复用既有 UI；除非有明确的可用性、性能或业务依据，不进行大规模改版。
- UI 调整须保持操作路径和数据语义连续，并完成桌面与窄屏检查。

## 强制阶段门禁

开始任何下一阶段、下一流程或新的阶段计划前，必须先阅读本文件，并阅读下表中目标阶段要求的全部延期清单。

没有完成延期项复核，不得开始下一阶段开发。不得只阅读目标阶段主文档而跳过 `doc/后续流程`。

复核每个延期项时必须明确标记以下结果之一：

1. `本阶段实现`：纳入目标阶段开发流程、测试和验收。
2. `继续延期`：写明原因、触发条件和新的目标阶段。
3. `取消`：写明取消依据；重大范围变化需要 ADR。

完成复核后，必须同步更新目标阶段开发流程、FeatureCatalog、Migration 清单、已知风险和阶段验收记录。

## 单一来源规则

- 延期事项的详细内容、目标阶段、触发条件和状态只保存在 `doc/后续流程`。
- 阶段开发文档和总路线只保留当前交付范围及指向本目录的链接，不再复制延期明细。
- 同一延期项出现冲突时，以本目录中的最新清单为准。
- 延期能力不得用空页面、空结果或虚假成功冒充已实现。
