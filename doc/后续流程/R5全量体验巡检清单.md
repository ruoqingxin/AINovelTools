# R5 全量体验巡检清单

## 状态

- 开始日期：2026-09-02
- 阶段决定：R6 暂不进入实施；先完成 R0-R5 的真实桌面体验与问题收集。
- 目标：验证用户真实工作流，而不以自动化通过替代产品体验。

## 推荐体验路径

按顺序完成以下路径。每条路径应记录成功、失败、卡顿、难理解或数据异常的地方。

1. 新建项目、打开最近项目、关闭并重新打开项目。
2. 创建规划节点、修改规划、检查修订历史与恢复。
3. 创建章节、编辑正文、制造并处理冲突、检查正文历史。
4. 配置模型与密钥，完成一次连接测试。
5. 分别执行续写、重写、润色和摘要；检查 Proposal 的预览、接受、部分接受和拒绝。
6. 对一次生成执行取消；使用临时错误 Key 验证鉴权失败后正文与历史不被污染，随后删除错误 Key。
7. 创建、修改、归档和检索 Story Bible 实体；从搜索结果进入关联章节。
8. 创建 Fact 和 EvidenceAnchor，完成候选审核、冲突处理、章节定稿，并检查 KnowledgeVersion 与 WorldState。
9. 创建、编辑、筛选、退回复核和归档关系、事件、信念与伏笔。
10. 执行备份、恢复到新目录、健康扫描、诊断包与启动恢复检查。
11. 在宽屏和窄屏窗口完成上述关键路径，检查溢出、遮挡、焦点、滚动、空状态和错误提示。

## 问题记录模板

每个问题单独追加一条记录：

| 字段 | 内容 |
| --- | --- |
| 编号 | `UX-YYYYMMDD-序号` |
| 路径 | 上述体验路径编号和操作步骤 |
| 预期 | 用户认为应发生的结果 |
| 实际 | 实际结果和是否可恢复 |
| 影响 | 阻断 / 严重 / 一般 / 轻微 |
| 复现 | 稳定复现 / 偶发 / 未复现 |
| 环境 | 窗口尺寸、项目数据规模、模型配置或错误信息 |
| 证据 | 截图、日志、章节或实体标识 |
| 处理 | 待分析 / 已修复 / 不处理 |

## 退出条件

- 关键路径至少完整体验一轮。
- R4 延期中的真实云端动作、取消、鉴权失败和宽窄屏人工证据完成或重新明确延期。
- 阻断与严重问题已修复或有明确处置决定。
- 基于实际问题复核 R6 候选能力是否存在真实触发条件。
