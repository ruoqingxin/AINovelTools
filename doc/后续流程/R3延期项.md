# R3 延期项

## 前端展示 UI 固化标准
- 前端展示 UI 在不影响性能的前提下，必须美观、清晰、易用。
- 首次实现功能时确定布局、信息层级、视觉规范、控件规范、完整状态和响应式行为，形成稳定基线。
- 后续功能优先复用既有 UI；除非有明确的可用性、性能或业务依据，不进行大规模改版。
- UI 调整须保持操作路径和数据语义连续，并完成桌面与窄屏检查。

## R3 完成前仍需执行

### 真实云端 API 冒烟

1. 保存 DeepSeek 或 OpenAI `CHAT` 配置及 Key，执行连接测试。
2. 保存硅基流动 `EMBEDDING` 配置及 Key，确认连接测试返回向量维度。
3. 分别执行续写、重写、润色和摘要，观察流式预览和 Proposal 记录。
4. 取消一次生成并制造一次鉴权失败，确认正文和修订历史不变。
5. 接受及部分接受 Proposal，确认只改变未保存草稿；显式保存后才新增 `ManuscriptRevision`。

真实云端冒烟通过前，R3 FeatureCatalog 保持 `PARTIAL`。API Key 只能在本机桌面 UI 中录入，不得写入文档、聊天、日志或项目数据库。

## 目标 R4

- Character、Location、Faction、Item、Concept 等长期知识库。
- EntityRevision、别名、标签、归档和来源版本过滤。
- SQLite FTS5 关键词检索、索引重建和本章相关资料查询。
- 章节 L0-L5、人物 L0-L3 等多精度摘要与压缩材料的基础数据。
- 风格规则卡、少量样例和写作技巧卡的正式管理入口。
- 检索结果接入 `ContextAssembler` 的结构化查询和关键词查询阶段。

R4 建立数据和检索来源，但检索结果和 AI 新生成细节仍不能自动成为正式事实。

## 目标 R5

- Relation、Fact、Event、Belief、Foreshadowing 和 `EvidenceAnchor`。
- 故事当前状态、人物知识边界、物品和位置等 `WorldState` 投影。
- 人类可读结果加机器可读 JSON 的双输出及 Schema 校验。
- `facts_used`、`possible_conflicts`、`new_content_candidates`、变更记录和自检报告。
- 独立生成与独立审核调用，以及候选知识的人工批准流程。
- `ChapterChangeSet`、知识审核、冲突检测和章节定稿。

这些输出会进入知识治理，必须等正式领域类型、证据锚点和审核事务具备后再启用。

## 目标 R6 或以后

- 使用专门 AI 制订检索计划或上下文计划。
- 关系检索、向量索引、混合检索和高级 `ContextAssembler`。
- 长章节按场景规划、逐场景生成、状态接续、合章和多轮审核。
- 顾问、规划、执行、审核和协调等多角色工作流。
- 多模型审核、完整 Task Runtime、独立 Worker 和复杂工作流。
- Tantivy 全文索引及大型数据集性能工程。

以上能力必须同时遵守 `长期按需能力与延期项.md` 中的触发门槛。

## 延期原则

- 不为延期能力建立空 UI 或无真实调用者的抽象。
- Embedding 模型、维度或分块版本变化时必须重新生成对应索引，不能混用向量。
- 向量本身不得进入聊天 Prompt；只发送检索命中的原文及来源信息。
- 将正文发送给 SiliconFlow 和聊天模型属于两个云端数据边界，启用前必须完成隐私确认。
