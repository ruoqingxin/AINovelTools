# 全局布局与交互优化方案

日期：2026-10-12

状态：阶段一、二已实施并完成前端自动化验收；阶段三至五待实施。原生桌面保存与恢复仍需实机确认。

## 1. 审查范围与结论

本次依据用户提供的项目页截图、当前前端路由与组件代码，以及仓库已有的桌面和窄屏验收截图进行梳理。已有截图只用于辅助判断布局，不作为当前全部页面已经实机验证的证据。历史设计文档仅作为产品背景，不替代本次需求，也不自动成为实施指令。

覆盖项目、规划、创作、讨论、资料、待处理、搜索、任务、设置，以及资料、正文、审核、模型配置下的二级页签。

核心问题不是功能不够，而是功能归属和操作语义不清：

- 创作活动、内容库、作品管理和系统维护被放在同一层导航。
- 同一个对象在多个页面出现不同名称的编辑、确认和检查入口。
- 局部操作被包装为独立页签，页面内部又叠加页签、阶段条和操作卡片。
- 保存、载入、采用、批准、定稿的区别依赖大段说明，而不是由按钮和状态直接表达。
- 主要工作区被标题、说明、模型参数和多层边框挤占。

优化目标：让用户始终知道“正在处理哪部作品、哪个对象、当前是什么状态、下一次点击会改动什么”。

不以单纯减少按钮数量为目标。删除重复表达，保留必要能力和数据安全边界。

## 2. 已核实的问题

| 问题 | 当前依据 | 优化决定 |
| --- | --- | --- |
| 左栏混合不同层级 | `app-shell.tsx` 中项目、创作模块、搜索、任务并列 | 作品管理和全局工具移出主功能导航 |
| “继续写作”不是继续上次位置 | `empty-project-view.tsx` 使用首个未归档章节；写作页另有上次章节记忆 | 统一按作品恢复上次章节；无有效记忆才回退首章 |
| 待处理页并非待处理清单 | `review-center-view.tsx` 提供准入、候选、知识三套检查面板 | 改为作者待办列表，打开既有处理界面，不再复制整套工作台 |
| 正文检查对象命名不一致 | 编辑器叫正文草稿，检查面板叫正文候选；审核中心依赖候选快照传递 | 统一对象名称，并明确检查所对应的草稿版本 |
| 正文工作区入口繁复 | 正文四页签、助手三页签、知识二级切换、检查对象选择 | 默认只有编辑器；阅读为模式，历史为抽屉，知识为局部工具 |
| 规划操作重复 | 正式主线/待定区中同时出现多个“保存待定候选”入口 | 每个编辑对象只有一条保存操作区 |
| 规划有多个导航体系 | 规划树、分组阶段条、上一项/下一项、总览阶段卡 | 保留一套内容导航；阶段状态改为辅助信息 |
| 创建章节依赖规划页 | 写作空状态要求先去规划建立章节；常规结构创建在分卷管理中 | 写作页可直接创建章节，复用同一结构操作 |
| 构思结果有两条并行保存链 | 讨论消息可保存候选；构思草稿又可整理为实体和设定 | 一个收集入口，按目标执行明确的后续操作；保留历史候选 |
| 作者规则和正文事实易混淆 | 作者设定、实体、知识记录分散，术语需要说明才能区分 | 展示来源和状态，不能把作者设定自动当作正文事实 |
| 摘要有效状态重复操作 | 摘要行同时提供恢复摘要、设为有效、恢复为有效 | 按当前状态只显示一个明确动作 |
| “重建摘要”不等于重新生成 | `materials_store.rs` 的重建指令修改状态及生成模式，不重新计算内容 | 手工恢复状态与实际重新生成必须分开，不能用同一文案替代 |
| 技术字段暴露在默认表单 | 实体固定属性 JSON、来源版本；知识事实 ID、证据区块；卡片作用范围 | 默认用可读名称和对象选择器，原始字段进入高级信息 |
| 系统维护重复曝光 | 搜索页重建索引，任务页新建系统维护任务并手动执行下一项 | 维护操作归数据管理；后台活动只负责进度、结果及允许的重试/取消 |
| 子页面导航定位不完整 | 主导航使用精确路径匹配，资料有多个子路由 | 子路由始终保留所属主功能的选中状态 |
| 视觉规则多次叠加 | `App.css` 存在多段根变量和布局覆盖，另有局部页面样式 | 确立共享规范后逐页替换，停止在文件末尾不断追加补丁 |

## 3. 推荐的信息架构

### 3.1 全局框架

```text
顶部：作品选择 | 当前对象位置                    搜索 | 后台活动

主导航        当前功能的内容导航       主工作区           按需辅助区
写作          章节目录                 正文编辑器         写作助手
构思          讨论列表                 对话               构思笔记
大纲          作品定位 / 主线 / 分卷   规划内容           AI 候选
资料          分类和列表               资料详情           来源信息
待办          类型和状态               待处理清单         打开对应处理界面

设置          全局配置 / 当前作品配置
```

主导航由八项业务/工具混排，调整为五项稳定入口：

| 新入口 | 主要职责 | 明确不承担 |
| --- | --- | --- |
| 写作 | 创建章节、编辑正文、使用 AI、检查当前正文 | 全书设定管理、独立复制的审核流程 |
| 构思 | 剧情讨论、记录备选、整理作者选定内容 | 直接改正文、自动写入已发生事实 |
| 大纲 | 作品定位、主线、分卷规划、章节结构 | 正文编辑、再建一份章节执行卡 |
| 资料 | 查询和维护作者设定、剧情记录、参考资料 | 待审核候选的另一套批准入口 |
| 待办 | 汇总需要作者决定的事项，定位原处理界面 | 发起检查、运行系统任务、展示全部历史 |

作品管理使用顶部作品选择器：切换最近作品、新建作品、打开作品、进入作品管理。未打开作品时显示精简的作品列表，保留新建和打开，不展示无效的创作按钮。

搜索是全局工具，不占一个常驻业务页签。后台活动是机器运行情况，不叫“待办”，不与作者需要决定的事项混在一起。设置固定在主导航底部。

### 3.2 唯一归属

每类对象只有一个规范编辑或处理界面。其他页面可提供带上下文的跳转，但不能另外复制一个行为不同的编辑器。

| 对象/行为 | 规范归属 | 其他页面如何关联 |
| --- | --- | --- |
| 正文编辑、保存、AI 替换 | 写作编辑器 | 搜索和待办定位到具体章节或候选 |
| 本章计划/执行卡 | 写作助手“本章计划” | 大纲点击章节打开同一面板 |
| 全书主线、分卷规划 | 大纲 | 写作只显示上游摘要和跳转 |
| 分卷与章节结构 | 共享目录操作 | 写作和大纲复用同一操作，不能独立维护两份结构 |
| 角色、地点、势力、物品、概念 | 资料中的“人物与世界” | 构思整理结果打开共用确认界面 |
| 作者规则与秘密 | 资料中的“作者设定” | 保留来源讨论、关联实体和公开状态 |
| 提取候选与事实审核 | 共用的候选处理界面 | 本章工具按章节过滤；待办按事项直接定位 |
| 历史修订与恢复 | 当前对象的历史抽屉 | 待办定位到对应异常草稿 |
| 系统维护 | 数据管理 | 搜索异常和后台活动仅提供跳转 |
| 模型设置 | 设置 | 业务页显示当前模型名称和紧凑调整入口 |

## 4. 全部页签的调整方案

### 4.1 项目页：调整为作品选择与管理

- “项目/工程/作品”在面向作者的界面中统一称为“作品”；文件夹路径放在作品详情中。
- 新建和打开保留为明确命令；当前作品在列表中直接标记，不再重复展示相同信息。
- 打开已有作品恢复上次工作位置；“继续写作”不得固定进入第一章。
- 新作品默认进入可用工作区，允许直接创建第一章；“先写一段看看”“一起规划”不再作为长期并列主按钮。
- 一句话创作方向可在创建流程中填写，但不强迫补齐人物、结局、大纲。
- 有独立的作品管理入口，最近列表不会因为取消主导航“项目”而失去可达性。

### 4.2 创作页：调整为写作工作区

默认呈现章节目录、正文编辑器和按需展开的助手。选中章节后直接进入编辑，不先展示介绍页或流程总览。

| 当前入口 | 调整后的表达 |
| --- | --- |
| 编辑 / 已保存正文两个并列页签 | 同一正文区域的编辑/阅读模式；阅读显示已保存版本 |
| 版本 | 章节工具栏的历史图标，打开版本与异常草稿抽屉 |
| 知识 -> 提取候选 / 事实审核 | 一个“本章知识”工具，按真实状态呈现提取及待确认事项 |
| AI 创作 | 助手中的“AI 写作”，操作类型使用单一模式选择 |
| 本章计划 | 同一助手中的计划编辑区，保留独立于正文的保存行为 |
| 检查 / 检查正文 / 候选审核 | 一个“检查正文”命令，运行结果显示在助手内 |
| 创作准入 / 创作准备 | 生成操作附近的“生成前检查”；内容完整度建议不伪装成保存门槛 |
| 查找章节与目录 | 目录展开时直接搜索；收起时用一个章节选择入口打开同一目录 |

正文操作区只保留保存正文这个主操作；检查是次操作。放弃本地草稿、手动合并等放入更多操作，只在相关状态出现时显示。

保存状态统一在编辑器操作区呈现，区别“草稿已保护”“待保存正文”“正文已保存”。页签、标题、正文上方不再重复给出互相冲突的“未保存”提示。

AI 写作根据上下文展示已有能力：整章生成、续写、选区改写、选区润色、摘要。选区操作没有选区时给出明确状态，不引导用户误以为会修改整章。

候选结果使用明确动作：“插入末尾”“替换选区”“替换整章”“不采用”。替换有改动的整章必须预览和确认；采用只改变编辑草稿，保存正文仍是独立动作。

历史恢复统一称为“载入编辑器”，不直接覆盖已保存正文。保留对比、异常草稿保护和产生新修订的行为。

### 4.3 规划页：调整为大纲工作区

- 主内容导航按“作品定位、故事主线、分卷与章节”组织，不同时保留规划树、横向阶段导航和多个“继续下一步”。
- 现有十五项设定仍保留数据和能力。默认展示常用条目，其余通过展开分组访问，不要求用户填完十五项才能开始写作。
- “作品设定”改为更明确的规划名称“作品定位”，与资料中的人物、规则和正文事实区分。
- 作品定位、主线、分卷采用相同布局：当前内容、AI 命令、候选预览、唯一操作区。
- 正式版本默认只读，点击编辑进入新草稿；修改状态与内容在同一个保存区提交，不再单独摆“保存状态”和“保存内容”两个相近按钮。
- AI 指令直接命名“生成主线”“生成分卷方案”“拆分本卷章节”，不使用泛化的“AI 推导”“生成候选”作为不同任务的同一名称。
- 分卷生成、手工新建和章节拆分不全部堆在长页面上。根据当前对象与操作展开对应工具。
- 生成分卷/章节后用结构化列表预览，允许选择、改名、编辑内容后创建；不要让作者依靠固定文本格式才能成功采用。
- 选择章节打开其规范计划面板，不在大纲页再次维护另一份执行卡。
- 原有未知、暂不决定、作者保留、锁定状态保留。规划不完整本身不能阻止手工写作。

### 4.4 讨论页：调整为构思工作区

- 统一使用“构思”作为主功能名、“讨论”作为会话对象名，取消页面中多种产品化名称交替出现。
- 讨论列表可折叠，正文对话为主体，构思笔记按需展开。
- 新建讨论默认全书范围和自由构思，可直接开始输入；标题可从首条内容产生。主题和章节范围是可选配置。
- 会话“构思类型”与草稿“构思主题”如果对应同一含义，只保留一个可编辑来源；实施前确认字段契约，不能仅隐藏其中一个造成状态不同步。
- 消息统一只有一个“收集片段”入口，目标菜单为选定内容、备选方向、未决问题、送往大纲。来源与状态随片段保存。
- 作者消息不自动等于已选定内容，AI 消息也不固定只能存入备选；由作者选择目标。
- “整理设定”根据已选定内容生成结果；结果明确是待确认内容，不直接入正式资料。
- 已有笔记、规划候选、设定候选、伏笔候选完整保留，通过统一入口访问。伏笔不能因为从讨论转出就绕过正文证据要求。
- 草稿自动保存正常时显示状态，手动保存作为辅助命令；不能出现自动保存一份、另一个同名按钮保存到不同位置的错觉。
- 整理结果与历史版本按需打开；默认不在一页中同时展开全部旧结果。

### 4.5 资料页：调整为四类清晰对象

| 分类 | 内容 | 默认界面 |
| --- | --- | --- |
| 人物与世界 | 人物、地点、势力、物品、概念 | 类型筛选、列表、详情；编辑按需进入 |
| 作者设定 | 作者确认的规则与尚未揭示内容 | 内容、公开状态、关联实体、来源 |
| 剧情记录 | 已确认事实、关系、事件、角色认知、伏笔 | 类型过滤、记录列表、证据与关联内容 |
| 参考资料 | 摘要、章节记忆、风格规则、写作技巧 | 摘要/写作卡片切换，选中后查看或编辑 |

- “实体库”“知识记录”“信念”等技术/领域术语替换为作者能直接理解的展示名称；底层类型不因此改动。
- 四类资料使用统一的列表与详情布局，不再有的默认新建、有的只读、有的左右摆两套大表单。
- 新建表单只在用户发起新建后出现；未选对象时不伪装成正在新建。
- 实体名称、类型、描述作为常规字段。JSON、版本标识、内部 ID 放高级信息；必要结构化属性用字段编辑器，保留原始 JSON 高级入口。
- 文件提炼放到“导入资料”命令中，使用独立流程选择主题、预览结果、确认，不嵌在每个实体的常规编辑表单里。
- 作者设定中的“关联实体”必须打开实际关联对象，而不是仅回到实体库首页。
- 正文事实与作者规则保留不同来源及知识边界。角色可揭示内容、作者知道的秘密与角色认知不能合并。
- 剧情记录类型使用一种筛选方式，不再在四个资料页签下面嵌一排长页签再叠一排状态按钮。
- 关系端点、事件参与对象和证据选择默认显示可读名称、章节与原文片段，原始 ID 不作为主要识别信息。
- 摘要状态按合法迁移显示一个对应命令，不能并列三个“恢复有效”。真实重新生成与手工恢复有效是两种行为。
- 自动摘要默认不能通过一键修改状态伪装成最新，保留来源版本与过期标识。
- 写作卡片使用启用开关，排序调整不能每输入一个数字立即发请求；确认后保存。
- 摘要和卡片详情也提供清晰的编辑入口，不让“可维护”仅表示创建和切换状态。

### 4.6 待处理页：调整为作者待办

当前该页主要是检查面板，不是实际队列。改造后以持久化的待确认事项为基础，不凭空制造待办数量。

默认显示事项、所属章节/讨论、问题类型、当前状态、需要的操作。高风险冲突优先，已处理事项默认收起。

- 知识候选、待确认设定、需要处理的异常草稿可以成为队列来源。
- 正文 AI 候选可展示并定位到写作助手；不能另设一套接受/替换正文界面。
- 未填写的规划项不自动变成待办；需要用户主动发起的检查不当作已存在的任务。
- “生成前检查”和“检查正文”由工作区发起，待办不重复提供同一发起表单。
- “已批准、待定稿”的事实和“尚未批准”的事实保持不同状态；批准不能假装已经完成定稿。
- 高风险冲突仍阻断知识定稿，不能通过精简 UI 绕过。
- 各类候选的处理界面共用呈现框架，但按真实对象显示不同动作与结果。
- 队列刷新、工作区状态和角标来自同一查询与状态定义；聚合查询不足时明确增补，不用一次遍历全部章节拼出不可扩展的队列。

### 4.7 搜索页：调整为全局搜索工具

- 所有业务页都能从顶部打开搜索，保留独立结果页支持深链接，不要求仅做狭窄弹窗。
- 输入关键词、选择内容类型、查看匹配片段、定位对象。结果显示中文类型、作品内位置和来源，不默认展示内部编码。
- 打开结果保留关键词、筛选和返回位置。正文搜索结果定位到命中的确切修订与原文，不能偷偷替换为最新正文。
- 索引重建移至数据管理。搜索失败可提供“前往修复”的入口，但不常驻维护按钮。
- 移除“短查询自动使用受限回退”等实现说明，不要求作者理解检索技术。
- 现有搜索不覆盖的对象不在界面承诺“全部内容”；新增作者规则或讨论搜索需单独确认索引和权限边界。

### 4.8 任务页：调整为后台活动

- 顶部全局入口显示运行数与需要处理的失败，打开进度列表或完整记录页面。
- 默认看进行中、失败和最近完成；主要信息是行为、目标对象、进度、结果。
- 任务与 AI 调用是不同数据。先统一显示语言和目标跳转，不在第一阶段强行把记录表合并。
- 后台调度和 AI 运行详情可通过同一活动详情访问；存在对应关系时关联展示，否则保留明确分类，不能猜测或重复统计。
- 正常任务自动运行。“执行下一项系统任务”退出普通用户界面，但不能改变现有执行模型而未做回归。
- 新建备份、恢复校验、健康扫描、重建索引改从数据管理发起。需要路径等参数的维护使用完整流程，不能继续暴露无上下文的按钮。
- 保留运行中取消、可重试失败的重试和清除失败提醒。清除提醒不删除错误记录。
- 最终请求、提示词版本、内部编号与日志放高级详情，API Key 不展示、不记录。
- 质量回顾归入用量/效果的分析视图，保留原入口兼容；不与实时任务并列争抢日常注意力。

### 4.9 设置页：保留职责，压缩默认复杂度

| 分类 | 调整 |
| --- | --- |
| 模型连接 | 配置列表与连接表单；常规字段为名称、服务、模型、地址、Key；限制和计费折叠 |
| AI 参数 | 默认模型与任务列表；有差异才显示覆盖标记；任务详情按需编辑 |
| 检查规则 | 明确当前作品；生成前检查、正文检查、知识审核分别控制，不用抽象阶段说明代替行为 |
| 用量与预算 | 用量、估算费用、预算及效果分析；软预算明确只提醒，不宣称强制限额 |
| 数据管理 | 将现有系统维护能力整理成可完成的操作流程；这是新增界面组织，不是已存在的设置页 |

- 本机模型连接、全局默认参数、当前作品覆盖和按作品统计的数据必须明确区分作用范围。
- 不能把所有设置放在一个“全局/项目”开关下面，实际不支持该作用域的项目不得出现虚假的切换。
- 首选模型与十类任务的自动继承保持现有行为；默认以紧凑列表显示任务、当前模型、覆盖状态，不展示十块相似大卡片。
- 温度等数字参数使用带值的滑块或数字输入；提示词、上下文开关、备用模型等进入高级设置。
- “测试连接”若保存当前配置，应明确命名“保存并测试”；否则应实现真正无副作用的测试，不能保留隐藏保存。
- 保存操作区统一，关闭或切换前处理未保存内容；不能用 UI 精简取消版本校验和错误反馈。
- 数据管理中的恢复使用明确来源和新目标目录，保留校验与确认，不允许隐式覆盖当前作品。

## 5. 统一操作与状态规则

### 5.1 明确区别，不使用一个“确认”覆盖全部

| 行为 | 推荐名称 | 实际效果 |
| --- | --- | --- |
| 普通正文保存 | 保存正文 | 从编辑草稿创建已保存正文修订 |
| 本章计划保存 | 保存计划 | 更新计划，不改变正文 |
| 自动保护草稿 | 草稿已保护 | 本地持久化成功，不等于已保存正文 |
| AI 规划候选采用 | 确认为主线 / 确认为分卷规划 | 写入指定正式规划 |
| AI 正文候选采用 | 插入末尾 / 替换选区 / 替换整章 | 修改编辑草稿，不直接保存正文 |
| 作者设定确认 | 确认设定 | 写入作者资料，不生成正文事实 |
| 事实审核通过 | 批准事实 | 进入待定稿状态，不直接成为正式世界状态 |
| 事实正式写入 | 定稿 N 条 | 完成既有原子定稿事务 |
| 载入历史正文 | 载入编辑器 | 保留旧修订，作者之后决定是否保存 |
| 不保留 AI 结果 | 不采用 | 更新候选决定，不删除正文或历史 |

可以合并呈现框架，不能合并不同状态机。尤其保留事实的批准与定稿边界；本轮不设计一个直接跳过审核的“确认全部”。

### 5.2 操作层级

- 一个对象、一条操作区、一个当前主操作。左右独立编辑对象允许各有自己的主操作，但必须标明目标。
- 新建、导入、生成、保存、确认使用准确动词，不能用“继续”“同步”“处理”代替实际结果。
- 低频行为放更多菜单；恢复、归档、删除按对象状态显示，不全部并排。
- 搜索、历史、刷新、收起、撤销使用熟悉图标，提供工具提示和可访问名称。
- 模型未配置时仍能手工写作；AI 操作显示原因和配置入口。
- 非破坏性操作不过度确认。替换内容、丢弃未保存内容、删除、恢复文件和知识定稿保留必要确认与预览。
- 同一个动作的快捷入口必须打开同一个规范界面；这是上下文导航，不是第二套独立实现。

## 6. 视觉与布局规范

方向：安静、清晰、适合长时间写作的桌面工具。使用中性背景、白色内容面、清晰深色正文及少量强调色，不把全页文字、边框和背景都染成蓝色。

| 项目 | 建议基线 |
| --- | --- |
| 顶部全局区 | 48-52 px，作品与对象位置稳定显示 |
| 主导航 | 112-136 px，图标配短名称，支持收起 |
| 局部列表 | 220-260 px，可折叠；不要再套一层装饰卡片 |
| 辅助区 | 320-360 px，按需展开，窄窗口用抽屉 |
| 控件 | 常规高度 32-36 px，触屏保证足够命中区域 |
| 标题 | 页面 20-22 px，局部 14-16 px，取消重复大标题 |
| 普通文字 | 控件 13-14 px，正文编辑 16-18 px；主要信息不能用 9-10 px |
| 阅读排版 | 正文区域保持适合阅读的行宽，宽屏余量给目录和助手 |
| 间距 | 4/8/12/16/24 px 固定层级，不用大片空白替代层次 |
| 圆角 | 常规 4-6 px，需要边框的容器不超过 8 px |
| 色彩 | 中性底色，蓝色用于选择/命令，绿色成功，琥珀警告，红色风险；附文字状态 |

页面结构以分栏、分隔线和工具栏建立层次。页面区块不做悬浮卡片，不在卡片里再套卡片；只有候选条目、弹窗等真正独立对象可采用有边界的容器。

取消常驻功能介绍、教程、技术说明和重复流程条。操作名称、字段名、当前状态、校验错误及必要的安全提示保留；不能为“干净”而隐藏操作后果。

滚动由工作区管理：章节列表、正文、辅助区各自明确，避免整页长滚动把保存和当前章节带走。操作区可在编辑区域内稳定可见，但不得遮挡正文最后几行。

响应规则以实际可用空间为准：

- 宽窗口可同时显示目录、正文、助手。
- 约 1024 px 优先保证正文宽度，目录与助手默认不同时常驻。
- 更窄时目录和助手使用可关闭的抽屉；主要导航仍能打开，不能仅靠隐藏侧栏解决溢出。
- 检查 1440、1280、1024、800、390 px 的关键界面；高屏缩放和键盘操作也要验证。
- 不按视口宽度缩放字体，不用更小文字掩盖溢出。长名称可换行或截断并可查看完整值。

## 7. 实施顺序

### 阶段一：统一归属与全局框架

交付主导航、作品选择器、全局工具区、未打开作品状态和统一页面容器；保留旧路由兼容，不删数据。

先建立功能入口清单、对象归属和文案字典，明确每个旧入口是保留、合并、迁移还是隐藏。资料子路由高亮和继续写作定位一并校正。

### 阶段二：完成写作与大纲主链路

交付默认编辑器、共享章节目录、写作助手、唯一计划编辑器、历史抽屉，以及规划统一编辑/候选布局。

“新作品 -> 新建章节 -> 写作 -> 保存 -> 重开继续”必须可独立完成；不依赖 AI 或完整规划。

### 阶段三：整理构思与资料

交付统一收集片段流程、设定确认、四类资料的列表/详情、文件导入流程和摘要状态命令清理。

保留旧讨论来源、作者秘密、实体修订、提取证据与正文版本，不能只迁移可见文本。

### 阶段四：改造待办与后台工具

交付真实待办列表、共享处理界面、后台活动和数据管理入口；记录聚合只在有可靠关联时执行。

队列查询、深链接和状态计数需要补充的接口应明确列出，不能把后台新增假装成仅调整 CSS。

### 阶段五：统一设置与全量验收

交付紧凑设置布局、作用域清晰标识、共享控件和样式规则；再做全页状态、窄屏和数据安全回归。

每阶段上线一个完整可用流程，不对所有页面仅做半成品外观替换。

## 8. 验收标准

1. 主导航仅保留五个业务入口；作品管理、搜索、后台活动、设置均仍可方便访问。
2. 每个旧功能都有明确去向，不因删除按钮而遗失导出、恢复、证据查看等能力。
3. 同一正文/计划/实体只有一个规范编辑界面，其他入口正确定位到它。
4. 同一工作对象没有重复保存按钮，没有无法说明区别的确认或恢复按钮。
5. 新作品能直接创建章节、手工写作和保存，不要求先完成大纲或配置模型。
6. 继续写作恢复本作品最后有效章节；切换作品不会沿用另一部作品的位置。
7. 草稿保护、正文保存、AI 候选确认、事实批准和知识定稿有清楚且一致的状态。
8. 编辑/阅读切换不能让用户误认为未保存内容已成为正式正文。
9. 待办只计入真实待处理事项，处理后工作区、列表和角标同步。
10. 搜索和证据跳转定位到确切对象/修订，返回时保持列表位置、关键词和筛选。
11. 旧深链接和历史来源保持有效，无效或跨作品链接明确报错，不偷偷打开另一条内容。
12. 载入历史版本保留原修订，异常草稿保护、并发冲突与未保存提示不退化。
13. AI 结果不会未经作者决定写入正文或正式知识；高风险事实冲突不能绕过定稿限制。
14. 作者设定、作者秘密、角色认知和正文事实的边界在重组界面后不改变。
15. 系统维护有完整参数、状态和失败处理；不要求普通用户手动调度后台队列。
16. 1440/1280/1024/800/390 px 关键页面无不可控横向溢出、遮挡或文字重叠。
17. 页签、菜单、抽屉可使用键盘，焦点明确；重要状态不只靠颜色区分。
18. 正常、空内容、加载、未配置模型、运行中、失败、未保存、远程版本变化都经过界面检查。

实施验证应复用现有路由、写作状态、候选保护、来源导航、批量事务及桌面恢复测试，并增加对应的界面验收。截图模拟 IPC 与真实桌面验证分开记录，不用模拟通过替代真实保存/恢复。

## 9. 范围边界

方案初稿只新增本文档。当前已按阶段一、二修改全局框架、作品入口、写作与大纲工作区、路由保护和相关前端测试；未改动数据库结构、原生保存/恢复流程或审核状态机。

实施默认保留现有 Tauri、React、查询缓存、正文修订、候选和知识模型，不新增大型工作流系统，不为界面精简重构数据库真值模型。

必要的新增工作包括待办聚合、结构化候选预览、数据管理流程等，应在对应阶段分别确认接口和测试范围。不能为了维持“纯 UI 改动”而用错误状态或不可完成的流程替代真实能力。

### 11.2 数据与操作边界

- 正文草稿保护、正式正文保存、本章计划保存、规划草稿保存、候选确认继续使用各自原有接口，不合并为一个泛化的“同步”。
