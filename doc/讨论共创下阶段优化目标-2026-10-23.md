## 1. 阶段定位

**让共创从“能完成执行”进入“依据准确、允许探索、能持续写作并可靠采用”的阶段。**

优先补齐重构决策中阶段 B 的真实创作闭环与阶段 C 的关键可靠性缺口，不继续用功能数量、提示词长度或正常结束轮数代表完成度，不将本轮规划视为阶段 A 至 E 或 AC-01 至 AC-40 全部验收。

本阶段四项核心交付：

1. 检索状态与操作回执准确，不能把无效、未执行、失败混成零命中。
2. 整段回复保留限定词、准确否定范围，区分讨论决定与正式采用。
3. 关键规则、限制与例外可被找到并实际送达，不用更多无关资料掩盖漏召回。
4. 同一工作区完成讨论、试写、局部修改和作者确认采用，连续写作保持视角与风格。

预算、权限、版本、隐私和恢复是以上交付的共同底线，不另设一轮“全面加功能”。

## 4. 各目标的范围与验收

### G1：检索状态和操作回执

目标行为：

- 从检索层提供结构化的查询有效性及执行状态，不靠匹配中文 `coverage` 文案判断。
- 有效零命中、无效查询、未授权/无索引而未执行、执行失败、部分覆盖分别表达。索引待更新是独立维度，不能与执行结果互相覆盖。
- 原始 `hits` 可以为空，但无效或未执行查询不能作为一次有效零命中参与结论；回执逐行说明原因，不只依赖底部通用免责声明。
- 分别保留查询、offset、范围、实际返回页、后续页、预算省略及索引观察时点。自由回复不能代替程序计数。

验收：构造有效 0 条、有效 4 条、单字无效、未调用语义服务、提供商/本地读取失败、索引待更新及分页/预算省略组合，逐项核对实际执行、审计与展示；不能合并成一次“没有结果”。这是确定性程序门槛，不需要等待模型随机触发。

### G2：整段语义边界与创作自由

目标行为：

- 已有资料中的“可能”“尚未确定”“普通术法”“一次性”等限定，在解释、括号、建议和结尾中保持含义，不只在首次引用时保留。
- “真伪未定”不写成“抄本已错”或作者故意留错；作者明确要求试写“抄本其实为真/为假”的版本时，可以探索，不能把提案回写为既有事实。
- 否定“无条件恢复全部记忆”只约束该命题，不自动否定部分、有条件或特殊机制；新点子可讨论，不用先正式修改资料才能提出。
- 来源位置、分支身份、正式状态、事实真伪是不同维度。相关性已确定不表示内容真伪已确定。

改进方向：先精简、组织已有上下文与规则表达，准确关联来源、原文限定和当前决定；模型提取出的条件仍是待核对解释，不能自动升级为作者规则。不以继续堆长提示、默认增加一个付费裁判调用或关键词替换器作为主要方案。

验收：对别名、冲突原文、准确否定、全面重构场景逐段审阅，含后半段和结尾；同时设置明确允许探索的正例，防止通过一律拒绝创作来消除错误。提示词字符串断言只证明规则已配置，不证明语义达标。

### G3：讨论决定与正式采用

目标行为：

- 新体系的 CHOSEN 决定可以指导本分支持续写作，与共享正式规则并存。
- 不仅因为二者不同就称正式资料过时、漏改、待同步，或生成既定的影响待办。
- 作者明确要求采用并更新资料后，允许先准备对应版本的差异，再由作者对界面展示范围确认；不制造“先确认才允许准备”的循环。
- 准备、接入工作稿、正式采用、关联对象更新分别以真实操作回执为准。

验收：成对验证“仅讨论不更新”和“明确要求准备采用并更新”；前者不制造正式义务，后者能走通实际差异与确认。不允许用全面禁止同步建议的禁词规则，破坏作者主动提出的更新流程。

### G4：关键规则召回与低噪声上下文

目标行为：

- 改述查询不能只找到体系名，却遗漏与当前回答直接有关的代价、限制和例外。
- 优先使用当前索引、名称/别名、检索排序和有限关联扩展；有实际缺口才补查。初始上下文已经包含足够、准确且成功送达的原文时，不为满足工具次数强制重复搜索。
- 低置信或覆盖不足时，进行有停止条件的改写/原文读取，或如实说明缺口；不悄悄改成较弱问题后宣称回答完整。
- 不依赖“九曜”“记忆”等固定测试词硬编码答案；不默认开启向量外发，不全量扫描全书或填入无关地点、角色秘密凑数量。

验收：

- 原固定改述场景的两份关键资料在初始召回或有限补查后均以准确版本送达；同时保留初始仅 1/2 时的原始指标，不能用最终覆盖改写初始召回。
- 新增改名、改代价及长文后段条件样例；分别检查关键条件和例外，不能只统计标题命中。
- 三档本地基线沿用 Recall@12 不低于 0.90、Noise@12 不高于 0.30、错误空结果率为 0；关键失败场景单独验收，不能被宏平均掩盖。
- 保留本地热查询 P95 20ms 的同环境观察线；它不是模型端到端 SLA。

### G5：自然回应与连续写作

目标行为：

- 回答当前问题，必要时才问方向；作者已确定沿用或重构后直接推进，不每轮重列三条路径和整套旧设定。
- 给出具体、可继续修改的创意或正文，允许提出有理由的异议，不把共创变成资料审核表。
- 从讨论切到试写，再局部修改，不复制上下文、不强制补齐规划表单；自然语言或已有工作区状态足以承接目标。
- 明确范围的“换第二个”能找回原方案；确实歧义才简短追问。只采用一个段落不等于采用整份回复。
- 连续三轮修改保持非目标文字、人称、视角、作者指定措辞及必要留白，不重复铺陈或退回旧情节。

验收：至少一条三轮以上的连续创作样例，包含作者指定风格/保留片段、叙事位置与一次局部修改；评阅每轮的实际创作产出、视角、风格、推进情况和重复确认负担，不能只用无矛盾或有引用代替。

### G6：完整闭环、预算与恢复

目标行为：

- 在隔离桌面项目上完成“已有设定发现 -> 作者选方向 -> 工作稿 -> 试写正文 -> 局部修改 -> 准备正文与设定关联差异 -> 作者确认 -> 后续读取新版本”。
- 普通真实模型固定集继续只准备、不自动采用。正式采用另建明确允许测试写入的隔离验收路径，通过真实界面展示和确认，不偷偷改变原评测脚本的权限。
- 只勾选独立子集不连带提交其余方案；已声明依赖缺失或过期时阻止相关提交。范围内依赖检查不冒充全量语义自洽。
- 保持先有效压缩、仍不足临时翻倍一次、仍不足保留进度并提示；不重放已执行工具、不永久修改设置、不扩大金额预算。
- 保留输入超限、输出截断、10 次调用上限、金额不足、账户/提供商错误各自原因；不把它们统一叫“预算不足”或自动重试。
- 中断恢复先核对新稿件、决定和修订；取消、追加指令、切换目标后，迟到结果不再自动覆盖。正式提交响应未知先查回执。

验收分层：

- 本机原生：默认预算、途中扩容一次、扩容后再次不足、无法扩容、取消/重启后版本改变、部分采用与响应丢失，记录是否发出 HTTP、是否重读/重复提交及不变保护。
- 真实模型：固定默认预算全量；另行批准后，在独立低输入预算配置中验证途中扩容及再次不足，不改原配置，不保证能自然触发，未触发仍记未覆盖。
- 真实项目：至少一个空白项目与一个经作者授权的迁移后长篇副本，完成闭环及备份还原；无副本或外发授权时，该项保持未验收，不能拿合成六卡替代。
