# DeepSeek 测评问题优化修复

日期：2026-10-23，Asia/Shanghai。

依据：`DeepSeek讨论共创真实评测-2026-10-23.md` 的五类生产缺陷。原始真实测评与人工评阅文件保持不变。

## 1. 本批结论

首轮修改生产共创运行器，提示词升级到 `coauthor-v16`；同日追加预算单位修复为 `coauthor-v17`（第 8 节），再按用户确认加入单轮临时扩容策略，为 `coauthor-v18`（第 9 节）。数据库仍为 65，IPC 仍为 188 个命令、4 个事件。

本批没有调用收费模型，没有读取真实模型配置或作者真实项目，也没有自动沿用上次剩余预算。完成的是执行逻辑修复、提示规则补强及本机原生确定性回归，**不宣告 DeepSeek 语义质量或三目标效果验收通过**。

## 2. 当前请求与旧历史隔离

- 本轮作者原话单独作为最后一条用户消息，不再埋在检索、工作稿和历史共用的 JSON 中。
- 旧历史仅放在 `contextOnly` 参考数据中，保留原角色、消息身份、时间、截断标记及关联决定的最新状态，不再重放为独立用户指令。
- 复用现有 `DiscussionRelevance` 排序和片段提取，相关决定关联优先，保留有限的最近消息帮助理解指代；最多 6 条，受本轮预算的八分之一约束。超长单条历史不再导致后面的短相关历史全部丢弃。
- 最新决定单独突出；新增 `initial_decisions` 与 `context_assembly` 审计，记录实际装入的决定、历史消息身份和规模。它们是上下文组装记录，不冒充提供商已经成功收到。
- 提示规则明确当前请求优先；“继续之前决定”仍不清楚时先 `get_decisions`，不因无关旧话题要求作者重新选方向。

这不是完整长期记忆或语义指代解析。词面相关性仍可能漏召回，未关联旧建议仍需模型核对，不能据此声称任意长历史已解决。

## 3. 不确定性与重构边界

- 明确保留“可能”“尚未确定”“普通术法”等限定词。原文事实、当前决定、未决状态、推测、新提案和正式资料分开。
- 不允许把真伪未定说成确定错误或作者故意保留；不从一份资料未描述规则推出整个地域无规则；不把普通术法限制扩大成任何术法都不行。
- 未选方向时开放沿用延伸、局部调整、全面重构；作者已经明确选定后推进，不重复协商。
- 明确全面重构后，旧代价、例外和道具仅供对照，继承是可选提案，不是新体系的强制前提。

这两类属于模型语义行为的提示约束，不是程序已经能判定所有推论是否有据或所有重构是否优秀。仍须同场景真实模型回归及人工评阅，不能以提示词断言替代质量证据。

## 4. 准确改稿回执

- `edit_draft` 返回实际修改的 `before/after`、实际建议文档预览、基础版本，以及 `prepared=true`、`applied=false`、`formalCommit=false`、`syncsOtherSources=false`。
- 先在副本上验证修改，失败不留下部分文档变动。成功建议仍不直接写入保存稿件或正式资料。
- 有净文档建议后，后续模型自由文字不再作为流式改稿回执；最终及检查点回复由程序从实际建议文档生成，不让模型凭记忆重写境界名或采用状态。
- 短稿给准确全文预览；长稿给首次变化附近的 Unicode 有界节选并明确标注，不拿未变的开头冒充改动范围。
- 回执说明运行器只准备建议，界面核对后可接入工作稿；这不代表正式提交，更不会自动同步设定卡或其他正式资料。
- 取消、失败或达到上限的运行即使留下局部建议，也明确说明本轮未完成，不把局部建议说成全部请求完成。

本批不改变界面已有的版本核对及工作稿建议自动接入资格，也不新增正式写入权限。为消除错误预览，存在文档建议的最终回执采用确定性文字，不保留模型在该阶段自由生成的改稿说明；完整工具记录仍可追查。

## 5. 查证纠错、阶段压缩与分类收尾

- 判断版本不匹配时继续拒绝，不自动替换 revision 或重新提交判断；返回结构化 `recovery`，要求重新查询清单并逐字使用准确版本，明确参数抄错本身不证明资料真实变化。
- 成功落库判断后，可将该清单、资料身份、准确版本的已送达原文换成判断摘要。失败、未判断、其他清单及其他修订的原文不压缩，普通原文读取不因此自动裁剪。
- 预算不足时先移除初始检索导航和旧历史，再把已成功落库的读原文及判断调用/结果对合并到 `checkAssessments` 阶段检查点。当前原话、最新决定、权限、选区、工作稿定位、未判断原文和错误记录保留。
- 阶段检查点标明属于派生判断，不是作者决定、正式事实或新的原文读取。调用与结果按各自 assistant 轮次匹配，跨轮重用调用身份不会删除另一轮未判断原文；剩余工具协议仍成对。
- 压缩只修改后续模型上下文，不改原始审计、读取/送达回执、数据库判断或正式采用的版本保护。
- 结束时从持久化台账生成相关、无关、不确定及未判断汇总。只列首批条目时明确分页，不能把首批当全集；状态过期、未读、未送达、未判断及待核对继续可见。
- 达到字符预算或轮次上限时仍保留分类与准确清单身份，可继续查证；没有提高原来的 32768 字符预算或 10 次模型请求防护。

这不是无限上下文或全书自动分析。大量未判断原文、长期检查点及工具定义仍可能超过预算；跨轮仍走现有清单、分段笔记恢复和按需重读。

以上是首轮 `v16` 的字符防护；第 8 节追加修复已将判断单位改为估算 tokens，首轮记录保留为历史证据。

## 8. 追加：输入预算单位修复

用户指出预算不足后，继续核对配置、执行层和原始真实用量，确认共创运行器把界面的 `inputTokenBudget` 直接当作序列化字符上限使用。真实失败请求链路的字符数已超过 32768，但最后成功请求的提供商输入仅 11551 tokens，不能据此认定 DeepSeek 上下文装不下或账户余额不足。

修复内容：

- 复用应用层原有混合文本 token 估算：ASCII 连续字符约四字一个 token，非 ASCII 按 Unicode 标量逐个计数。共创对完整序列化消息及全部工具定义计算，再增加 20% 估算余量、每条消息 16 tokens 和 512 tokens 协议预留。
- 输入预算仍受讨论配置、模型上下文减最大输出及 1024 tokens 安全预留、原有 32768 tokens 防护三者共同约束。没有提高默认预算、增加模型请求次数或扩大费用授权。
- 修正共享预算函数的下限抬高问题：模型扣除输出和安全预留后只剩 128 或 0 tokens 时，不再反向增加到 256。其他任务的既有上下文校验会拒绝不足的预算，共创则在请求前保留明确的停止原因。
- 导航压缩和查证检查点均按估算 tokens 决定是否触发，不再因大量 ASCII 工具 JSON 而提前丢弃上下文。已落库原文压缩、版本保护、未判断原文保留及完整审计规则不变。
- `model_request`、`budget_limit` 和压缩审计分别记录 `inputChars`、`estimatedInputTokens`、`inputTokenBudget` 或压缩前后的估算量。字符统计改为真正的序列化字符数，不再把旧公式的 512 协议预留混入字符数。运行账本的输入估算改用 tokens；提供商真实 usage 存在时仍优先使用真实用量。
- 真正超预算时明确列出估算量及可用上限。首笔被拦时明确“尚未发送模型请求”；查证中途触顶时保留清单进度及继续入口。不截断作者本轮原话或未判断证据来强行发送。
- 达到单轮 10 次请求上限时单独记录 `MODEL_REQUEST_LIMIT`，即使已有部分输出或工作稿建议也说明本轮未完成，不再笼统叫作 token 预算耗尽或费用不足。
- 本机评测新增 `--loopback-input-tokens`，只能配合 `--loopback` 使用且限制 256 至 32768；不能用它覆盖真实收费运行的配置。回归按估算 tokens 校验，不再要求 `inputChars <= 32768`。

边界：这仍是带余量的本地估算，不是 DeepSeek 专用 tokenizer、严格 token 上界或精确账单。大量中文原文、任意长请求、持续增长的检查点仍可能真实触顶；不自动扩大预算、不无限续跑，也不把未送达原文冒充已送达。真实模型语义效果仍需单独授权复测。

## 9. 追加：本轮一次性自动扩容

用户确认采用“预算不足时自动翻倍一次，再次不足才提示调整”的方案。以下策略替代第 8 节中“不自动扩大预算”的旧行为，历史回归和原始真实测评记录不改写。

- 适用范围仅为共创的输入上下文 token 预算。每次请求仍先尝试导航和已完成查证检查点压缩；压缩后足够就不扩容，也不消耗本轮唯一一次扩容机会。
- 仍不足时，临时预算取初始值的两倍、模型可用输入容量、65536 tokens 应用保护上限中的最小值；只有确实能提高上限才扩容。初始值为 32768 时可达到 65536，旧的共享 32768 上限不再挡住本功能。
- 共创尊重作者显式设置的高于 32768 的输入值，但初始及扩容值均不得超过 65536 和模型可用输入容量。其他 AI 任务沿用原预算策略；未设置输入值时仍用原有默认机制，不因功能上线永久提高默认值。
- 模型可用输入容量复用共享计算：模型上下文减实际最大输出，再减 1024 tokens 安全预留。不会为扩容挤占输出空间，也不会把容量为 0 或 128 的模型反向抬高到最小配置值。
- 扩容只是更新当前运行内存中的上限，继续当前消息、工具结果、查证台账和工作稿建议；不重建运行、不重放已执行工具、不从头重做，也不重置单轮 10 次模型请求计数。
- 扩容后仍不足，或之后再次增长到上限，保留结果并停止；明确显示估算需求、初始预算、扩容后的上限和“已扩容一次，不再自动扩容”。模型或应用上限已经限制扩容时如实提示，调整配置不能突破物理容量。
- `input_budget` 审计记录初始和最高允许值；`input_budget_expansion` 记录唯一一次变更、`configurationPersisted=false` 和 `taskRestarted=false`。后续请求及触顶审计保留初始预算与扩容状态，进度事件也显示本轮临时上限。
- 不改写讨论设置、项目覆盖配置或金额预算，不自动重试提供商、账户余额、费用中继拒绝等错误。**更多输入 tokens 可能增加真实费用，本功能不保证费用不变，也不是金额预算自动翻倍。** 既有授权及费用中继边界继续有效，本批验证只使用本机提供商。
- 本机回归逐轮检查讨论配置、金额预算设置、保存工作稿和正式资料快照不变；实际 HTTP 请求数另行计数，与运行审计对照。新增仅限回环的 `--loopback-expect-input-limit`，用于验证扩容一次仍无法发送首笔请求的预期停止；该模式不会把 `LIMIT_REACHED` 改写为 `COMPLETED`，也不能用于绕过收费授权。

## 10. 修复后真实复测反馈的第二轮优化

### 10.1 限定词、否定范围与来源身份

- 限定词约束整段回复，包括括号、后续建议、总结和决定记录，不能先说真伪未定再称“抄本的错”。
- REJECTED 只否定决定内容的准确命题；否定“无条件恢复全部记忆”不等于禁止有条件、部分恢复或特殊机制的提案。“普通术法”不扩成绝对不可恢复，新机制仍需作者选择。
- 尚未确定沿用、局部调整或全面重构时，不把“新定”直接当沿用，不能只提供“接后面/插中间”或先排除某种代价；已选方向后不重复协商。
- 模型收到的初始关键词/语义候选和后续原文读取增加 `provenance`，由真实来源类别生成 `PROJECT_SHARED` 或 `CURRENT_BRANCH_HISTORY`。资料位置不证明内容真伪，也不授予当前决定身份，正文内容不能改写来源元数据。
- 初始及后续决定结果增加 `decisionScope`，明确当前分支身份、准确否定范围、不更新正式资料、不自动产生同步要求。不同体系的讨论决定与正式规则可以并存，不凭差异判定正式资料过时或制造待办。
- 是否同步仍须作者另行要求，原有“准备差异、界面确认采用”流程及正式写入权限不变。元数据只用于模型上下文和运行审计，数据库仍为 65，IPC 仍为 188 命令、4 事件。

以上语义规则和位置标识改善模型依据，不是通用自然语言事实验证器；本机测试不能证明真实 DeepSeek 在所有段落中都会遵守。

### 10.2 由结构化记录生成检索回执

- 初始检索及工具检索分别记录准确查询、offset、本分支历史/项目资料范围、当次返回数、后续页、预算省略数和独立索引状态。
- 有追加检索或查证清单时，程序生成检索操作回执；每条查询独立计数，不把“星砂契约”0 条与宽查询 4 条合并成 0。
- 返回数不是相关条数、全库总数或查全证明；异常及缺失结果不计成 0 命中。语义未授权或无可用索引时明确 `NOT_RUN` 和“未调用向量服务”，不是一次零命中的提供商查询。
- 最近一次语义索引快照与当前查证索引使用不同标签；前者为当时观察，不冒充当前全局状态，也不相加。
- 回执显示最近 12 次操作，超出的明确提示见完整审计；不为了展示上限删除原始记录。查询按 JSON 字符串转义，换行不能伪造另一条回执。

普通讨论保留模型自由回复，程序回执是操作计数依据；提示词要求模型不重述计数，但不能声称任意自由文字已被程序语义纠错。

### 10.3 查证收尾与有效压缩

- 实际开始或推进范围查证后，最终查证回执直接来自持久台账，不再拼接模型自由收尾。模型原始文字保存在 `model_check_analysis` 审计中，不删除不佳表现。
- 最终显示范围、真实读取/送达/判断、分类、引用和未决状态。全部条目已处理但仍有 UNCERTAIN 时，明确“各项已处理，仍有不确定项，疑点尚未解决”，不改写 `complete=false`。
