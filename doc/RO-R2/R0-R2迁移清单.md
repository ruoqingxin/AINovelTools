# R0-R2 Migration 清单

## 前端展示 UI 固化标准
- 前端展示 UI 在不影响性能的前提下，必须美观、清晰、易用。
- 首次实现功能时确定布局、信息层级、视觉规范、控件规范、完整状态和响应式行为，形成稳定基线。
- 后续功能优先复用既有 UI；除非有明确的可用性、性能或业务依据，不进行大规模改版。
- UI 调整须保持操作路径和数据语义连续，并完成桌面与窄屏检查。

| 版本 | 名称 | 内容 | 状态 |
| --- | --- | --- | --- |
| 1 | `initial_core` | `schema_migrations`、`app_metadata` | 已完成 |
| 2 | `plan_nodes` | 规划节点、父子关系、排序索引 | 已完成 |
| 3 | `plan_node_revisions` | 规划节点历史记录 | 已完成（兼容表） |
| 4 | `manuscript_revisions` | 正文不可变修订、内容哈希、文档 Schema 版本 | 已完成 |
| 5 | `immutable_revisions_and_recovery` | 正式 `plan_revisions`、`recovery_logs`、历史更新/删除保护触发器 | 已完成 |
| 6 | `separate_chapter_entities` | 独立实际章节实体，解除正文对规划节点职责的直接依赖 | 已完成 |

## 说明

- `plan_nodes` 和 `manuscript_revisions` 的当前状态是投影，历史修订表是追加数据源。
- Migration 必须在真实临时目录和 SQLite 文件上执行一次打开、关闭、重新打开测试。
- 任何新增字段或索引都必须追加版本，不修改已发布 Migration 文本。
