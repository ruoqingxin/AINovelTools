# R0-R2 复核清单

## 前端展示 UI 固化标准
- 前端展示 UI 在不影响性能的前提下，必须美观、清晰、易用。
- 首次实现功能时确定布局、信息层级、视觉规范、控件规范、完整状态和响应式行为，形成稳定基线。
- 后续功能优先复用既有 UI；除非有明确的可用性、性能或业务依据，不进行大规模改版。
- UI 调整须保持操作路径和数据语义连续，并完成桌面与窄屏检查。

执行基线：`doc/总/修订版设计与实施路线.md`

## 现在完成

### R0

- Workspace、Tauri、React 和三层 crate 可运行。
- 项目创建使用临时目录和原子完成，支持关闭和重新打开。
- SQLite Migration、WAL、foreign keys、busy timeout 和健康检查已固定。
- FeatureCatalog、统一 IPC 错误码、契约验证和质量门禁已接入。
- 损坏 manifest、损坏数据库、重复创建和真实 SQLite 重开测试已补齐。

### R1

- PlanNode 类型、合法父子关系、稳定排序、移动和循环检测已完成。
- 前端规划写操作统一使用 `expected_version`。
- 正式 PlanRevision 只追加写入，历史 UPDATE/DELETE 被数据库触发器拒绝。
- 归档父节点时归档直接子节点；恢复只恢复当前节点。
- 实际 Chapter 已从规划节点职责中分离，Migration 6 建立独立 `chapters` 表。

### R2

- Tiptap JSON、Schema 版本、block ID、SHA-256 和稳定修订排序已完成。
- ManuscriptRevision 使用追加写入，并通过数据库触发器禁止修改和删除。
- `base_revision_id` 冲突检查、block 级差异和基础三方合并已完成。
- RecoveryLog 自动保存、项目级发现、章节恢复和正式保存后清理已完成。
- 未保存正文在章节切换和窗口关闭时会提示。
- 并发冲突、恢复重开、历史不可变和损坏项目测试已完成。

## 当前阶段结论

R0-R2 的核心业务不变量和数据安全链路已经具备。生产构建、前端测试、Rust 测试和 Clippy 已通过；真实 Tauri 桌面人工验收作为持续验收项保留，不阻塞 R3 开发。
