# R0-R2 阶段性总结

## 前端展示 UI 固化标准
- 前端展示 UI 在不影响性能的前提下，必须美观、清晰、易用。
- 首次实现功能时确定布局、信息层级、视觉规范、控件规范、完整状态和响应式行为，形成稳定基线。
- 后续功能优先复用既有 UI；除非有明确的可用性、性能或业务依据，不进行大规模改版。
- UI 调整须保持操作路径和数据语义连续，并完成桌面与窄屏检查。

## 1. 总体结论

当前实现已经形成一个可以运行的桌面原型：可以创建和打开项目，初始化 SQLite，创建规划节点，选择章节，使用 Tiptap 编辑正文，并保存正文修订。

2026-08-27 复核后，规划不可变历史、正文不可变修订、恢复、冲突检测、基础合并、统一错误和关键 SQLite 测试均已落地。非阻塞增强项已移入后续流程目录。

- Cargo Workspace、pnpm Workspace 和 Tauri + React 应用。

- 项目目录创建、打开、关闭。
- 项目创建使用临时目录和原子重命名。
- 项目目录包含 `project.json`、`project.sqlite`、附件和恢复目录。
- SQLite 初始化、WAL、foreign keys、busy timeout。
- 编号 Migration，目前 Schema 版本为 6。
- 基础 Health Query。
- 增加 `FeatureCatalog` 静态能力目录。
- Health Query 区分 `PROJECT_HEALTHY` 与 `NO_PROJECT_OPEN`。
- `cargo clippy --workspace --all-targets -- -D warnings` 已通过。
- 基础 Tauri IPC 命令。
- Rust 单元测试、SQLite 集成测试和前端基础测试。

### 2.2 R1 已完成或基本完成

- Tiptap 编辑器接入。

## 3. R0 缺失与需要优化

### 3.1 必须补齐

- 建立静态 `FeatureCatalog`，维护 `DECLARED`、`PARTIAL`、`IMPLEMENTED`、`DISABLED` 状态。
- 建立 Rust 类型到 TypeScript 类型的生成验证，避免 IPC DTO 手工漂移。
- 将 Health Query 区分为“核心服务健康”和“当前项目未打开”，避免无项目时显示“数据库不可用”。
- 补充统一的错误分类和前端错误展示，不直接依赖字符串错误信息。
- 补充 R0 验收报告和 Migration 清单。
- 修复 Clippy 错误，使以下命令通过：

  ```text
  cargo clippy --workspace --all-targets -- -D warnings
  ```

### 3.2 优化项

- 增加真实 Tauri 启动冒烟测试。
- 增加创建失败、重复打开、损坏 manifest、损坏数据库的测试。
- 增加项目关闭后的 UI 状态测试。
- 增加桌面环境下窗口启动失败的诊断信息。

## 4. R1 缺失与需要优化

### 4.1 必须补齐

- 将规划历史从“更新当前行并写日志”调整为正式不可变 `PlanRevision`。
- 当前状态可以作为投影，但历史修订必须成为正式数据源，不能只作为审计记录。
- 增加规划节点类型约束，例如作品设计、总纲、分卷、章节、场景的合法父子关系。
- 增加 `expected_version` 乐观并发检查。
- 增加移动节点操作，并防止非法循环或跨层级移动。
- 明确归档节点对子节点的处理规则。

### 4.2 优化项

- 规划树按 `parent_id`、`sort_order` 稳定排序。
- 节点标题修改增加未保存提示。
- 节点编辑、归档、恢复增加关键交互测试。
- 将规划树从当前单页面拆成明确的规划工作区路由。

## 5. R2 缺失与需要优化

### 5.1 必须补齐

- 增加 `document_schema_version`。
- 增加 `base_revision_id`，明确编辑草稿所基于的版本。
- 为正文块建立稳定 `block_id`。
- Rust 端验证 Tiptap JSON 的基本文档结构，不接受任意字符串作为正式文档。
- 使用稳定的 SHA-256 内容哈希替代默认哈希器。
- 修复“当前修订”排序不能只依赖秒级 `created_at` 的问题。
- 实现前端短期恢复和 Rust 持久化 `RecoveryLog`。
- 实现异常退出后的恢复入口。
- 实现基础冲突检测和三方合并，禁止静默覆盖。
- 区分“编辑草稿”“恢复记录”和“正式 ManuscriptRevision”。
- 增加正文修订只追加的数据库约束测试，明确禁止 UPDATE/DELETE 历史内容。

### 5.2 优化项

- 差异对比由简单按行号比较升级为真正的行级或段落级 diff。
- 差异结果支持定位到段落或 block ID。
- 保存按钮增加保存成功、失败和正在保存状态。
- 切换章节或关闭项目时增加未保存草稿提示。
- 增加编辑器快捷键和基础无障碍测试。
- 对 Tiptap 文档使用显式 Schema 版本迁移，而不是只做纯文本兼容。

## 6. 当前测试缺口

目前测试可以证明部分 Rust 数据层和 TypeScript 编译通过，但不能证明完整用户流程可用。缺少：

- 创建项目到规划树的真实 Tauri 流程。
- 创建章节、编辑正文、保存两次修订的流程测试。
- 修订历史刷新测试。
- 选择两个修订并显示差异的 UI 测试。
- 恢复旧修订后生成新修订的集成测试。
- 异常退出和恢复测试。
- Tiptap JSON 往返和旧纯文本迁移测试。
- 规划并发冲突测试。
- 真实临时目录和真实 SQLite 的恢复演练。

## 8. R0-R2 暂停验收标准

只有以下条件全部满足，才将 R0-R2 标记为完成：

- 创建、关闭、重新打开项目成功。
- 创建失败不留下有效半成品。
- Health Query 能区分服务健康和无项目状态。
- FeatureCatalog 状态真实反映当前能力。
- 规划修订不可覆盖，非法层级和并发冲突会被拒绝。
- 正文保存总是创建新修订，历史内容不可更新或删除。
- 正文文档经过 Schema 验证并具有稳定 block ID。
- 异常退出后可以恢复草稿。
- 恢复旧版本会创建新修订，不改写旧版本。
- 冲突不会静默覆盖。
- 两个正文版本可以可靠显示差异。
- Rust 测试、前端测试、类型检查和 Clippy 全部通过。
- 至少完成一次真实桌面流程验收。
