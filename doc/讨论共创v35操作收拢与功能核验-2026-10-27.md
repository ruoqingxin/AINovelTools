# 讨论共创 v35 操作收拢与功能核验

日期：2026-10-27。实用优先，本轮仅改共创前端及现有验收脚本，不改后端、数据库或 IPC 契约。

## 界面整理

- 主工具栏从五个讨论工具收拢为“依据与运行记录、讨论决定”两个入口；讨论删除仍独立显示并二次确认。
- “依据与运行记录”统一容纳“本轮记录、查证清单、检索设置”，不再各开独立面板。已打开的查证和检索表单在内部切换时保留。
- 本轮记录分为“本轮概览、检索回执、参考资料、运行步骤、改稿建议”，移除重复的改稿差异弹窗和概览跳转按钮。
- “工作稿版本、另开分支、分支比较与合并、关联变更”集中到工作稿页签。保留保存和正式采用，因为二者写入对象不同，不应合并。
- 目录刷新和详情刷新合并为一次“刷新目录与当前记录”。轮次优先显示已加载的作者指令摘要；无法取得指令时保留完整运行身份，不伪造题目。
- 窄屏记录页签保持单行；短原文不再强占固定高度。保留现有设计风格，无装饰性重构。

## 实际修复

- 工作稿“查看改稿建议”和全局记录入口始终打开最近一轮，不能因先前查看历史记录而误指旧轮次。回复内入口仍绑定该条回复的准确运行。
- 记录内明确标注“最近一轮 / 历史轮次”；历史、过期、未完成或无法核实的建议不能整稿采用。
- 操作失败及成功提示显示在当前面板内，并滚动到反馈位置，不再藏在弹窗背后。
- 未选择建议文字时禁止局部采用；采用后清除选择并禁用按钮，避免连续点击重复追加。明确展示选中文字将追加末尾还是替换工作稿选区。
- 有未处理恢复稿或版本冲突时，禁止采用建议，保留作者输入。
- 没有可用模型时显示原因及“配置模型”入口，而非只显示灰色发送按钮。
- 无讨论决定、无历史稿件、无改稿建议时有明确空状态。

## 操作用途与覆盖

以下为功能核验分组，不代表每个分支条件均做过真实模型端到端验证。

| 入口或操作 | 作用 | 本轮覆盖 |
| --- | --- | --- |
| 讨论 / 工作稿 | 切换区域，保留输入和稿件 | 组件、三种浏览器尺寸、原生 |
| 依据与运行记录 / 查看本轮记录 | 最近轮次或指定回复的准确运行 | 组件、浏览器、原生 |
| 轮次选择、分页、合并刷新 | 查历史与重新核实目录及详情 | 组件、浏览器；失败不当作空记录 |
| 概览、回执、资料、步骤、建议 | 分类查看，不挤入回复正文 | 组件、浏览器；回执原生核验 |
| 核对这条回复 | 追加核对请求，关闭改稿授权，不自动发送 | 组件、浏览器、原生 |
| 整稿 / 选中文字采用 | 仅改工作稿，保护版本和选区 | 组件；浏览器核验历史整稿禁用 |
| 查证清单 | 创建、分页、查看范围、带回继续指令 | 组件、浏览器；切换保留表单 |
| 检索设置 | 配置模型、授权、建索引、撤销与清理 | 组件；浏览器模拟授权和索引流程 |
| 讨论决定 | 纠正、历史、依赖项目与准确方案 | 组件、浏览器；版本冲突输入保留 |
| 工作稿版本、保存、正式采用、解除关联 | 恢复为新修订；区分工作稿和正式条目 | 组件及原生；界面操作后读取实际落盘结果 |
| 分支比较与合并 | 分支文字与决定分别比较、预览、确认 | 组件、浏览器 |
| 关联变更 | 多处正式内容的依赖核对、采用和撤销 | 组件、浏览器 |
| 发送、补充、停止、清空 | 控制本轮输入和生成，不覆盖新输入 | 共创组件测试；浏览器模拟发送 |
| 新建、另开分支、删除 | 独立讨论、复制方向、确认移除当前讨论 | 新建与另开分支原生落盘核验；删除组件、浏览器及原生核验 |

## 仍有边界

这是交互整理，不是模型语义质量达标证明。条件范围、新旧规则、前文承接仍可能出错，程序不能识别全部问题；记录缺失或运行完成均不能证明回答可靠。

浏览器使用模拟 IPC，原生验收使用合成本地资料，没有访问作者真实工程、调用付费模型或真实发送向量资料。关闭整个记录面板仍会卸载其中未提交的查证/设置表单；本轮只保证面板内部页签切换保留，不声称关闭后恢复。

单稿正式采用和多处关联变更语义不同，保留两者；已关联的正文和大纲仍不支持在此直接覆盖。删除是保留来源追溯的列表移除，不是物理擦除，也没有回收站恢复入口。
