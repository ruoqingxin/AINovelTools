# R5 ADR-001：知识证据与定稿边界

- 日期：2026-09-02
- 状态：Accepted for design

## 决策

R5 将“候选生成”“证据绑定”“人工审核”“正式定稿”拆成四个可审计步骤。AI 输出永远先进入候选或 Proposal，不直接写入 Fact、Relation、Event、Belief、Foreshadowing 或 WorldState。

## 原因

- R4 只能提供有来源的检索材料，不能把检索结果升级为事实。
- 正式知识必须能回溯到正文修订和 block 级证据。
- 冲突需要人工确认，模型不得自行合并高风险事实。

## 事务边界

候选创建、审核决定和定稿写入分别使用短事务；定稿在同一事务中写入 Fact 新版本、EvidenceAnchor、ChangeSet、审计记录和 Outbox 事件。任一校验、版本检查或来源检查失败时整体回滚，Outbox 不产生成功事件。

## 非目标

本 ADR 不引入向量索引、批量 ReviewCase、独立 Worker、多角色工作流或跨窗口会话治理。
