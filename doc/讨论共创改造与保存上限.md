# 灵感共创与保存上限

日期：2026-10-08。数据库 schema：48。

## 创作流程

灵感讨论 -> 构思草稿 -> AI 整理候选 -> 作者编辑并选择 -> 确认实体和作者设定 -> 写作上下文回用。

- 主题包括自由构思、角色、物品、环境与地点、剧情；名称和完整资料不是开始讨论的前置条件。
- 全书、分卷、章节、场景和选区仍可作为讨论背景。
- 已选定内容、备选方向、未决问题分别保存。AI 不得把备选全部合并成设定。
- 从实体库可以继续讨论已有实体。整理候选更新已有实体时保留版本检查、旧修订及原内容对照。
- 作者设定使用独立记录，保留实体修订、来源讨论、来源消息、候选和上下文版本。
- 作者保留的秘密默认不向读者揭示，也不能自动成为角色知识。
- 作者设定不伪造正文证据，不创建 Fact 或 WorldState。正文事实继续走原证据审核流程。

## 保存和读取上限

| 数据 | 上限 | 超限处理 |
| --- | --- | --- |
| 讨论标题、实体名称 | 200 字符 | 拒绝新提交，不修改已有数据 |
| 作者单条讨论、选区背景 | 20,000 字符 | 拆分发送，输入原文保留 |
| AI 单条回复 | 100,000 字符 | 拒绝超限写入，不影响旧消息 |
| 构思草稿三个部分合计 | 50,000 字符 | 拆分讨论，草稿原文保留 |
| 单个实体描述 | 50,000 字符 | 拆分设定 |
| 一条作者设定 | 5,000 字符 | 拆成多条规则 |
| 单次整理 | 20 个实体、总计 100,000 字符 JSON | 分主题整理 |
| 单实体规则、别名、标签 | 各 100 条 | 精简或拆分 |
| 会话、历史消息、草稿修订、整理候选、实体修订 | 不设置自动淘汰数量或过期天数 | 全部保留，实际受可用磁盘限制 |
| 消息界面读取 | 每页 100 条，IPC 单页最大 200 条 | 游标加载更早消息 |
| 草稿历史读取 | 每页 50 个版本 | 游标加载更早版本 |
| 整理历史读取 | 每页 20 个候选 | 游标加载更早候选 |

字符按 Unicode 字符计算。输入区不使用强制截断的 maxLength，超限仍可以编辑拆分。
构思草稿静止 1.2 秒后保存，仅有实际变化时追加新版本；历史恢复也创建新版本。
未发送输入和未保存编辑额外缓存到本机浏览器存储。浏览器缓存受浏览器容量限制，不替代项目数据库及备份。

## AI 上下文不是保存容量

- 普通讨论使用轻量作品背景，不沿用正文生成的逐项约束说明。已确认的题材、基调、世界设定和核心前提每项最多 200 字符，背景正文最多 1,200 字符；其余设定只按话题检索。
- 普通讨论总输入加设 24,000 个保守字符的上限，同时受模型可用窗口和任务预算限制。本轮问题完整保留；连问题与必要背景都无法容纳时拒绝请求，提示缩短或提高预算，不截断问题发送。
- 扣除角色提示、任务说明、本轮问题和标题余量后，先预留简短背景，剩余空间按构思记忆 25%、相关资料 30%、近期对话 30%、讨论范围 12%、其他参考 3% 分配。各部分还分别受 2,400 / 4,000 / 5,000 / 1,200 / 300 字符的绝对上限约束，较短的内容不会填充到上限。
- 相关检索优先使用本轮问题、已选定内容、未决问题和最近两条作者消息。关联实体直接保留，名称与别名优先；不使用未选定备选、旧 AI 建议或整个聊天历史扩展检索。没有相关资料时不凑数量，最多附加 8 个片段（含本书背景）。
- 实体简介、属性和相关规则从当前修订生成原文片段；长描述中的相关规则可以从中后段提取。没有额外 AI 摘要请求或向量服务费用，也不持久缓存会过期的实体摘要。
- 默认贴合本书但允许大胆发散和跨题材借鉴；只有明显转向或推翻重要设定时简短说明影响，作者主动探索或已接受的变化不反复警告。背景缺失不阻止讨论，也不猜定题材。
- 自由讨论和整理入库分开：整理仍只采用作者已选择的内容，不补写未决项，候选须经作者编辑确认。
- 普通讨论读取最近 12 条消息，最近对话上下文最多 5,000 字符，之后还受分配预算约束；优先保留最新消息。
- 构思记忆来自当前草稿的作者已选定内容、未决问题和少量备选，始终区分状态，不把旧聊天猜成作者结论。原有会话导航记忆最多 12,000 字符，继续保存但不再重复发送给普通讨论；原始消息始终保留。
- 整理读取最近最多 500 条消息，并优先保留完整构思草稿。
- 整理输入预算不超过模型可用窗口及任务设置，并加设 120,000 的保守输入 token 预算上限。
- 原始讨论部分最多 80,000 字符且不超过预算的一半，优先使用最近消息；不足时逐条排除较早消息。
- 候选记录实际纳入的消息 ID 及遗漏条数。界面明确提示遗漏，不能声称已整理完整历史。
- 完整草稿无法放入模型窗口时拒绝整理，提示精简或换模型，不修改已保存草稿。
- AI 整理输出最多 16,384 tokens，同时受模型输出上限和作者任务设置约束。

## 数据安全

新增表不会删除或改写旧讨论。
草稿保存检查预期版本，实体更新检查预期实体版本。
确认在同一事务内写实体修订、作者设定和候选确认状态，失败时整体回滚。
普通实体编辑继承上一修订的作者规则；新的讨论确认提供替代快照，旧规则仍留在旧修订中。

## 验证

自动化测试覆盖消息分页、Unicode 边界、超限不截断、重开项目、草稿版本恢复、
未确认不入库、确认事务回滚、版本冲突、作者设定与正文事实分离，以及写作上下文回用。
浏览器交互验证使用模拟 IPC，不调用真实模型，也不花费 API 额度。
