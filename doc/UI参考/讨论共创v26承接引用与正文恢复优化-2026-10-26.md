# 讨论共创 v26：承接引用与正文恢复优化

日期：2026-10-26。范围仍为 N2，本批只做根因修复与本机验证，新增收费调用 **0 次**，不沿用上批余额。真实基线见 [v25 真实报告](DeepSeek讨论共创v25协议优化真实复测-2026-10-26.md)，原始失败、报告和空白人工评分不修改。

## 根因与方案选择

v25 失败续写的上一回复为 866 个 Unicode 标量，完整进入上下文；四次请求输入均未超 32768，金额和十次请求上限也未触发。不能将它归因于历史截断或预算不足。

三次交付正文都是同一份 452 字文本，SHA256 为 `27a4924072d535c720b2ca341c383789e138e43e53ea1af76513089e1a40bc25`。模型先误填 USER 消息身份，再修正 AI 身份和承接句，但始终没有按连续 80 字复用错误重写正文。旧协议让生成模型同时手抄 UUID、承接原句和创作正文；身份前置失败可先阻断正文校验，完整失败稿又继续留在下一请求中。

采用既有单模型循环上的窄方案：

1. 程序提供承接短引用，身份和准确原文绑定交给程序；模型只选择引用并生成内容。
2. 恢复反馈区分修参数与重写正文，同时返回重复片段、保留句和可选引用，不再只靠笼统错误句。
3. 重复交付被拒绝时，仅从后续请求移除该次失败正文，完整原参数留审计，减少对不合格稿的重复依赖。
4. 对整段范围、未读来源和临时/永久效果做定向提示改进；这些是语义问题，不能靠身份引用或已读证明宣布解决。

不新增固定规划/裁判调用，不换模型，不机械删除作者正文或自动改模式，不提高三次交付失败、十次模型请求或费用边界。

## 实现边界

### 程序承接引用

- 新请求的 `deliver_reply.continuation` 使用 `reference` 和 `preservedQuotes`；不再向模型要求 UUID/anchor。旧 `messageId/anchor` 仍能解析并执行原校验，禁止与 reference 混用。
- 只有实际放入首个程序上下文的 ASSISTANT 历史条目得到 `history-N`；引用元数据先计入历史序列化预算，再决定是否送出，不额外偷加预算。
- `read_source` 读取 MESSAGE 的首段、具有执行层生成的 ASSISTANT 角色前缀且正文至少 8 字时，才附 `read-N`。普通来源、USER 历史、非零偏移和失败结果不发引用。
- 引用从当前请求实际保留的上下文/工具结果解析，不维护跨轮注册表。压缩移除原文后引用随之失效，须重新检索、读取；后续作者消息里的仿造 JSON 不能授予引用。
- 程序从实际送达内容取不超过 200 字的准确承接片段，保留当前分支、消息角色、读取/送达及当前运行保护；更早消息仍回查执行层的规范角色。短引用只绑定 AI 消息身份，不证明模型选中了消息内的第二方案或理解了剧情。

### 正文恢复

- `recovery.action` 为 `REPAIR_ARGUMENTS` 或 `REGENERATE_CONTENT`，附 `contentMustChange`、首个连续 80 字重复片段、作者许可的保留句、当前可用引用和剩余交付次数。
- 即使旧格式先错选 USER 身份，也独立检查近期 AI/本轮已送达历史正文的复用，首笔失败即可要求同时重写内容。更早的 `read_source` 历史不在最近 16 条内时也覆盖，不只检查近期列表。
- 只有判定正文必须变化时，替换本次 assistant 工具调用参数中的 `content` 为拒绝标记；原始参数及结果已先进入审计，并追加 `reply_recovery_context`。作者消息、已接受内容、保留句声明和其他参数不改。
- 校验仍拒绝非指定旧段；模型原样重交仍失败，不给自动修正文。普通 DISCUSSION 不作全局去重，作者明确要求 REPRINT 仍允许；本机专项验证失败/取消正文没有 text 事件，合格正文只发一次。

### 语义策略与预算

解释现行限制优先完整引用原句；没查全只能描述已读范围，不作全项目无支持资料的否定。新机制逐项标出新增部分，不能以“我建议”随后又声称完全兼容。先确定新效果临时/永久，再保持高潮和收尾一致。原有普通方法限定、合取否定、单件次数和选定新体系边界保留。

这些不是通用语义验证器：模式误报、短句改述、没有连续 80 字的重复、消息内混案和整段逻辑仍须真实回复与人工逐段评阅。`ruleChanges=[]` 不是未改规则的证明，准确读到/送达也不是理解正确。

既有输入策略保持：先压缩，再仅本轮最多翻倍一次，受模型容量和 65536 保护；再次不足保存进度并提示调整输入预算，不重启任务、不永久修改设置、不增加金额预算。
