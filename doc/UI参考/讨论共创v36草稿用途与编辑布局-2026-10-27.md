# 讨论共创 v36：草稿用途与编辑布局

日期：2026-10-27。

## 用途

工作稿是当前讨论里可编辑、可保存的稿件，不等于讨论回复，也不等于正式设定、大纲或正文。只讨论想法时无需使用工作稿。需要留下可修改的文本时，可将回复放入工作稿，整理后再预览并确认正式采用。

“允许改工作稿”控制模型是否可以提出并自动应用工作稿修改，不代表授权写入正式内容。本轮没有改变这个权限边界。

## 改动

- 工作稿区域标题改为“草稿编辑”，显示“仅保存在当前讨论”或“已关联正式内容”的实际状态及保存版本。
- 常用区域保留采用类型、保存、正式采用、标题和正文；叙事与关联信息、版本与分支等次要内容默认收起，不再挤占编辑区。
- 标题字号统一为 16px，标题和正文有明确输入边界，正文编辑区至少 200px。窗口高度不足时区域内可滚动，不让字段互相挤压覆盖。
- 回复头部增加“放入工作稿”。空稿直接放入；已有文本先确认追加，取消不修改原稿。保留原消息、当前输入及已有工作稿，不自动改变正式内容。
- 放入工作稿只提取回复正文，剥离符合旧版完整格式的检索回执，不改写原消息。放入后切换到工作稿并给出未正式采用提示。
- 生成、操作忙碌、版本冲突或存在未处理的本地恢复稿时，禁用此操作。

## 边界

工作稿仍是纯文本编辑器，不提供 Markdown 渲染或富文本排版。“放入工作稿”是正文复制，不会自动提炼回复中的分析、纠正错误或校验来源。正式采用前仍需人工整理和核对。
