# 讨论共创 N2 整段约束与续写优化

日期：2026-10-26。依据：[v22 修复及真实复测](讨论共创N2实测反馈修复与复测-2026-10-26.md)。本批为原 N2 的继续优化，不进入 N3 或 R6/R7。

## 范围与边界

- 针对一次性条件在情节中失效、新提案冒充原规则、连续续写重贴的问题，调整执行提示和历史输出身份；不加入自动语义真值表、固定规划/裁判调用或事后自动删改模型回复。
- 用户补充允许本机验证后最多 3 次真实调用；本批按最多 3 次实际 DeepSeek HTTP 请求理解，以发送前硬上限执行，不等于 3 批全套测试。只选已冻结的部分恢复场景，费用另设 3 元上限，无重试或备用模型，失败不重跑筛选。
- 不修改原固定集、本机 N2 集、独立对照集、既有真实报告及评分。只用隔离合成项目，未授权真实作者外发或正式采用。
- 无数据库、公开 DTO/IPC、迁移或依赖变化，schema 65、188 命令/4 事件保持。FeatureCatalog 不新增“语义已解决”能力；已有运行时能力及延期决定见 [范围复核](后续流程/讨论共创下阶段复核-2026-10-23.md)。

## 已实施

1. `coauthor-v23` 明确按情节执行顺序核对主体、动作、触发、次数与例外。一次机会耗尽后不能再次使用；改成持续通道/多次租借仍是新机制，改名字不能证明兼容。
2. 沿用规则时豁免下一次升阶代价须说明是局部改规则；商品颜色/尺寸不推出能力。总结分别说明沿用、新增和改变，个人避坑偏好不充当原规则禁令；继续允许假设、真假试写和有意识重构。
3. 历史 AI 输出增加 `PRIOR_ASSISTANT_OUTPUT` 及不能确立规则/作者决定的元数据；保持原文字、历史相关性/数量/预算上限和决定版本保护。选案后只写新增进展，作者要求重贴/整合全文的正例不受禁止；截断导致承接不明时先读本分支历史。
4. 真实评测 CLI 增加 `--max-model-requests`，在读取配置/启动前验证；中继发送前按已预留请求计数，结算和费用余量不能释放调用次数。账本分别标识请求上限、金额不足、提供商超额，不把次数不足冒充金额不足。
5. 评测记录本轮开头在同场景上一轮完整输出中原样出现的最长长度与 Unicode 位置，80 字以上列作阅读候选。该值只观察，作者可能明确要求重贴；不自动评分、不作阻断、不删改正文、不产生模型请求。

## 验收风险

本批仍主要改善模型约定与上下文身份，不能程序证明自然语言推论或情节兼容。重复观察只覆盖本轮开头的逐字复用，不检出换词重述、段中重复或混案；单句保留/重贴请求不能因指标被自动拒绝。提示变长使本场景实际输入增加 512 tokens，成本与预算开销继续观察，不新增每轮固定审核模型调用。
