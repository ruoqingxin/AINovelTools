# R3 启动前置清单

## 前端展示 UI 固化标准
- 前端展示 UI 在不影响性能的前提下，必须美观、清晰、易用。
- 首次实现功能时确定布局、信息层级、视觉规范、控件规范、完整状态和响应式行为，形成稳定基线。
- 后续功能优先复用既有 UI；除非有明确的可用性、性能或业务依据，不进行大规模改版。
- UI 调整须保持操作路径和数据语义连续，并完成桌面与窄屏检查。

## 已具备的前置能力

- 项目、规划和正文均有稳定 ID。
- 正文修订只追加，支持 `base_revision_id` 冲突检查。
- RecoveryLog 与正式 ManuscriptRevision 已分离。
- FeatureCatalog、Migration 和 IPC 错误契约已建立。
- Tiptap 文档具备 Schema 版本和稳定 block ID。
- 正文保存、恢复、冲突和历史差异均有 SQLite 测试覆盖。
- 前端可在章节切换和窗口关闭时提示未保存内容。

## R3 第一批实现范围

按文档顺序只实现以下纵向切片：

1. `ModelProfile`：Provider、模型 ID、上下文限制、隐私等级和超时设置。
2. OS Secret Store：只保存 `SecretRef`，前端不可回读完整 Key。
3. OpenAI-compatible `ModelGateway`：先支持非流式和流式文本、取消、超时、有限重试。
4. `ContextAssembler`：当前章节、选区、章节规划和相关实体占位来源。
5. `AiProposal`：生成结果先进入候选，不直接写正文。
6. 首批功能：续写、重写选区、润色选区、章节摘要。

## R3 不提前实现

- 通用 Agent、ToolGateway、多 Agent 调度。
- 向量检索、Tantivy、复杂工作流和独立 Worker。
- 正式知识提交、ChapterChangeSet 和章节定稿。

## R3 每项功能验收要求

- AI 调用失败不能改变已有正文。
- AI 输出必须带任务 ID、目标版本、上下文版本和 Prompt 版本。
- AI 输出只能创建 `AiProposal` 或编辑草稿。
- 接受 Proposal 后仍须通过正文保存命令生成新修订。
- API Key 不进入项目数据库、日志、诊断包或前端回读状态。
- 所有 Provider 错误统一映射为稳定错误码。
