# R3 第一批阶段验收记录

## 前端展示 UI 固化标准
- 前端展示 UI 在不影响性能的前提下，必须美观、清晰、易用。
- 首次实现功能时确定布局、信息层级、视觉规范、控件规范、完整状态和响应式行为，形成稳定基线。
- 后续功能优先复用既有 UI；除非有明确的可用性、性能或业务依据，不进行大规模改版。
- UI 调整须保持操作路径和数据语义连续，并完成桌面与窄屏检查。

## 已实现

- `ModelProfile`：明确区分 `CHAT` 与 `EMBEDDING`；DeepSeek/OpenAI 用于文本任务，硅基流动用于 Embedding。
- OS Secret Store：API Key 写入系统凭据库，项目库只保存 `SecretRef`。
- Chat ModelGateway：DeepSeek、OpenAI API 和通用兼容接口，支持非流式、SSE 流式、取消、超时、最多 3 次有限重试和稳定错误码。
- EmbeddingGateway：调用硅基流动 `/embeddings` 并校验返回向量；不建立向量索引和检索。
- `ContextAssembler`：当前章节、选区、章节规划、TokenBudget、上下文版本和 R4 实体占位来源。
- `AiProposal`：任务、目标正文修订、上下文版本、Prompt 版本、原始输出和审核状态持久化。
- Proposal 全部接受、部分接受和拒绝；接受只修改编辑草稿，不直接创建正文修订。
- 续写、重写选区、润色选区和章节摘要四个首批动作。
- Migration 7：`model_profiles`、`ai_tasks`、`ai_proposals` 及 Proposal 不可变身份触发器。
- Migration 8：增加模型能力字段，已有硅基流动 Profile 自动迁移为 `EMBEDDING`。
- 章节工作区已固定为四页签，规划树与节点详情采用响应式左右分栏。

## 尚待人工验收

使用真实云端账户和 API Key 执行一次桌面冒烟：

1. 保存 DeepSeek 或 OpenAI `CHAT` 配置及 Key，执行连接测试。
2. 保存硅基流动 `EMBEDDING` 配置及 Key，确认连接测试返回向量维度。
3. 分别执行续写、重写、润色和摘要，观察流式预览和 Proposal 记录。
4. 取消一次生成并制造一次鉴权失败，确认正文和修订历史不变。
5. 接受及部分接受 Proposal，确认只改变未保存草稿；显式保存后才新增 `ManuscriptRevision`。

真实云端冒烟通过前，FeatureCatalog 保持 `PARTIAL`。
