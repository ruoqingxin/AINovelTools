# R3 AI 创作闭环开发流程

## 前端展示 UI 固化标准
- 前端展示 UI 在不影响性能的前提下，必须美观、清晰、易用。
- 首次实现功能时确定布局、信息层级、视觉规范、控件规范、完整状态和响应式行为，形成稳定基线。
- 后续功能优先复用既有 UI；除非有明确的可用性、性能或业务依据，不进行大规模改版。
- UI 调整须保持操作路径和数据语义连续，并完成桌面与窄屏检查。

## 1. 目标与边界

R3 只建立可审计、可取消、失败不污染正文的 AI 创作闭环：

```text
模型配置和系统密钥
    -> 上下文组装
    -> 模型任务
    -> AiProposal 候选
    -> 接受 / 部分接受 / 拒绝
    -> 编辑草稿
    -> 用户显式保存为新的 ManuscriptRevision
```

本阶段实现续写、重写选区、润色选区和章节摘要。不实现通用 Agent、工具调用、多 Agent、向量检索、正式知识提交、章节定稿或独立 Worker。

## 2. 不可违反的规则

1. 模型失败、取消和超时不得改变正文或创建伪成功 Proposal。
2. API Key 只进入 OS Secret Store；项目数据库只保存 `SecretRef`，IPC 响应不返回 Key。
3. 每个 AI 结果必须记录任务 ID、目标正文修订、上下文版本和 Prompt 版本。
4. AI 输出只创建 `AiProposal`，接受 Proposal 只修改前端草稿，不直接创建正文修订。
5. Provider 错误统一归一为稳定错误码，日志和错误信息不得包含 Key、完整 Prompt 或完整响应。
6. 上下文采用最小充分原则，当前章节、选区和章节规划优先；相关实体在 R4 前保持显式空来源。
7. 用户输入的是自然语言创作要求；系统先编译为版本化的 `system/user messages`，再由 Provider Adapter 转换为目标云端 API 请求。

## 3. 实施步骤

### Step 1：领域和 IPC 契约

- 定义 `ModelProfile`、隐私等级、AI 动作、任务状态和 `AiProposal` 状态。
- 定义稳定 Provider 错误码、上下文快照和 TokenBudget。
- 为所有输入执行边界校验。

验收：领域测试覆盖空模型 ID、非法超时、需要选区的动作和 Proposal 状态迁移。

### Step 2：持久化与 Secret Store

- Migration 7 创建 `model_profiles`、`ai_tasks` 和 `ai_proposals`。
- Profile 只持久化 `secret_ref`；Key 使用系统凭据库保存和删除。
- Profile 查询只返回 `has_secret`，不可回读 Key。

验收：SQLite 往返、Proposal 不可直接写正文、密钥不进入项目库。

### Step 3：ContextAssembler

- 输入当前章节、目标正文修订、当前草稿、可选选区和章节规划。
- 按 TokenBudget 截断低优先级内容。
- 生成稳定 `context_version`，并标记相关实体来源为 R4 占位。

验收：同一输入产生同一上下文版本；选区任务缺少选区时拒绝执行。

### Step 4：ModelGateway

- 只使用云端 Chat Completions API，不提供本地模型部署入口；首批提供硅基流动预设和通用 OpenAI-compatible 配置。
- 支持非流式、流式预览、取消、超时和有限重试。
- 将 HTTP、鉴权、限流、超时、取消、协议和网络错误归一化。

验收：使用本地模拟服务覆盖成功、流式、取消、超时和错误映射。

### Step 5：AI 任务与 Proposal

- 创建任务时固定目标修订、上下文版本和 Prompt 版本。
- 仅在模型成功后创建 Proposal。
- 支持接受、部分接受和拒绝；保留原始输出和决策结果。

验收：失败任务无 Proposal；状态迁移有校验；历史候选可查询。

### Step 6：桌面交互

- 提供模型配置、密钥写入和连接参数界面。
- 提供续写、重写、润色、摘要动作，流式显示预览并允许取消。
- Proposal 可应用全部或选中文本到编辑草稿，也可拒绝。
- 应用后仍显示未保存状态，必须由用户点击“保存正文修订”。
- 章节工作区固定为“正文编辑 / AI 创作 / 修订与冲突 / 恢复草稿”四个页签；新增相关功能必须归入既有页签，不得继续堆叠到单一页面。
- 规划树与节点详情采用左右分栏，保持结构浏览和当前工作对象同时可见；窄屏降为上下布局。

验收：加载、空、运行、取消、成功、失败和无选区状态均可见且不会覆盖正文。

### Step 7：质量门禁与阶段记录

- 运行 `cargo fmt --check`、`cargo test --workspace`、Clippy、前端测试、类型检查和生产构建。
- 更新 FeatureCatalog、Migration 清单、R3 验收记录和已知限制。

## 4. 完成判定

四个首批动作均能通过同一闭环产生 Proposal；Key 不可回读；取消和失败不改变正文；Proposal 应用后必须再次显式保存才生成新修订。以上条件和全部自动化质量门禁通过后，R3 才可标记完成。
